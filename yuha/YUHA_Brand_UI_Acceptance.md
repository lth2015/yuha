# YUHA 品牌、UI 与动效验收规范

版本：1.0 · 日期：2026-09-20 · 适用：桌面及移动 Web · 交付对象：产品、设计、Claude / Codex、前端与测试。

**品牌：YUHA / 羽花 / ユハ。主标语：让心动，有回声。**

本文件确定设计基准和后续产品验收标准。随包预览是可操作的设计样例，没有接入生成、音频、账户或支付服务；不能据此判定业务已经开发完成。实际应用的验收项在取得证据前均为 `NOT_RUN`。本文件覆盖此前项目文档中的临时品牌、配色和视觉样式；已有的业务规则、版权条件、计费规则、架构和上线门槛继续有效。

## 1. 品牌要表达什么

一片花瓣微微翻起，让人看见本来无形的风。YUHA 把一个人暂时说不清的感觉，变成可以听见的音乐。识别符号采用向上舒展的抽象小写 y，同时保留花瓣、羽翼的联想；这些是品牌创作意象，不是对中日文词源的解释。

设计关键词：**轻、舒展、有留白、有一点俏皮**。酷感来自清晰的轮廓、醒目的比例、克制的颜色和准确的反馈。首版采用暖白的明亮界面，作品和创作输入是视觉中心。不要自行增加霓虹背景、满屏粒子、拟真录音棚、复杂调音台或没有真实数据的热度榜。

### 唯一主标语与本地化

| 场景 | 文案 | 使用方式 |
|---|---|---|
| 中文主标语 | **让心动，有回声。** | 官网首屏、启动海报、品牌介绍 |
| 日语对应表达 | ときめきに、響きを。 | 面向日本用户的同一品牌主张；上线前做母语文案校审 |
| 英语对应表达 | Let a feeling echo. | 国际页面中的同一品牌主张 |

同一页面只展示当前语言的一句主标语。海报中的其他短句是说明性配文，不是第二条主标语。页面功能说明另写清楚，例如「描述一种心情，创作一段 30 秒纯音乐」；仅凭标语不承担产品解释。

正式品牌名称写作 `YUHA`；Logo 图形里的字标固定为小写 `yuha`。中文辅助名写作「羽花」，日语读音标注「ユハ」。三种写法无需同时塞进导航栏。

## 2. Logo 母版与使用规则

### 2.1 结构

符号由两块不对称的花瓣形面组成：一块从左下向右上舒展，一块从左上折入，尖端相接形成 y 的联想。字标为自绘圆端线条，单层 a、小写 h 和下伸的 y 形成节奏。全部字形已写成 SVG 路径，不依赖用户设备安装字体。

**随包 SVG 是唯一母版。** 品牌效果图中的立体花瓣、纸张、灯光只作氛围参考，不用于反向描摹或代替导航 Logo。

| `assets/yuha-logo-mono.svg` | 单色印刷、低分辨率环境 | 墨黑 |

### 2.2 尺寸与安全空间

- 横向 Logo 保持 `328:100` 的画布比例。桌面导航宽 128px，移动导航宽 112px；其他使用不小于 112px。
- 独立符号常规显示不小于 24×24px；16×16 favicon 使用单色版，必须在实际 1× 像素下检查是否可辨识。
- Logo 外侧安全空间不小于显示画布高度的 1/4；独立符号为其画布边长的 1/4。安全空间不计入文件已有的留白。
- 应用图标按方形画布输出 192、512px PNG。SVG 内圆角用于预览；应用商店或系统要求无圆角母版时另按其模板导出，不能把预览图直接宣称为所有平台的上架资产。
- 不拉伸、不加描边、不改两片形面的相对位置、不给字标加阴影或渐变。导航栏标志始终静止。
- 24px 以下不叠加「羽花」或标语；彩色照片上放 Logo 时必须给足稳定的纯色承托区。

## 3. 颜色与基础样式

`tokens.css` 和 `design_tokens.json` 为机器可读交付。新增样式先使用 token，避免各页面单独发明近似色。

| Token | 色值 | 用途与约束 |
|---|---|---|
| `bg` | `#F6F5F0` | 主背景，暖白 |
| `surface` | `#FFFFFF` | 输入区、弹层 |
| `surface-soft` | `#ECEEE7` | 非交互底、禁用态、音频占位 |
| `ink` | `#20221F` | 正文、标题、主按钮背景 |
| `muted` | `#61665D` | 次级说明、时间、占位文字 |
| `line` | `#D8DAD3` | 纯装饰分隔线、卡片边线；不承担必要控件识别 |
| `control-line` | `#7B8177` | 次按钮、未选标签等必要控件边界 |
| `petal` | `#F46B45` | 品牌花瓣、少量强调色块；色块上用墨黑字 |
| `petal-soft` | `#FFE4D8` | 柔和封面、提示承托区 |
| `link` | `#A33F22` | 需要橙色文字时使用的深色版本 |
| `focus` | `#5748B9` | 浅色界面键盘焦点环 |
| `success` / `warning` / `danger` | `#28704B` / `#855619` / `#B33131` | 成功、注意、错误；同时提供文字或图标 |

普通正文实际前景 / 背景对比度至少 4.5:1，大号文字至少 3:1；按照字体实际大小和粗细判断。不要在花瓣橙上使用白色小字。必要控件边界与焦点指示要求至少 3:1；装饰线不作为控件唯一边界。参考：[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

默认首屏中，除专门的品牌插画和作品封面外，橙色用于 Logo、状态点或小范围强调，不铺满导航、所有按钮和所有卡片。主要 CTA 用墨黑底白字，每个独立操作区只突出一个主操作。

作品封面可用低饱和薰衣草 `#E8E3F5`、鼠尾草 `#E1E7D9` 作为背景。它们不代表付费等级、质量评分或音乐类型；正式封面的生成映射应根据作品 ID 固定，刷新不变色。

### 3.1 字体与层级

正文优先系统无衬线字体；中文、日文分别回退到设备的中文 / 日文字体。示例栈见 CSS。正式日语版根据 `lang=ja` 调整日文字体优先顺序，中文则用 `lang=zh-CN`。品牌字标使用 SVG，不用普通文本代替。

| 元素 | ≥1024px 桌面 | ≤767px 移动 | 字重 / 约束 |
|---|---|---|---|
| 首屏主标题 | 64px / 1.18 | 40px / 1.2 | 600；默认最多两行 |
| 页面标题 | 36px / 1.3 | 28px / 1.3 | 600 |
| 作品标题 | 32px / 1.3 | 26px / 1.3 | 500 |
| 正文、输入文字 | 16px / 1.65–1.75 | 16px / 1.65–1.75 | 400；输入文字不缩到 16px 以下 |
| 按钮、字段标签 | 14px / 1.5 | 14px / 1.5 | 500；关键字段标签可 600 |
| 次级信息 | 12px / 1.5 | 12px / 1.5 | 400 |
| 非关键装饰英文编号 | 11px / 1.4 | 最小 10px | 仅装饰性文字；不能承载条款、价格、错误或导航 |

平板标题 48px。字间距：中文正文默认，展示标题 -0.03em 至 -0.045em；日语版必要时恢复到默认字距，避免小假名拥挤。金额、时长和额度使用等宽数字。文案变长时换行，不压缩字体来硬塞。

### 3.2 间距、形状与质感

- 4px 基础网格，优先使用 8 / 12 / 16 / 24 / 32 / 48 / 64px；页面大分区间隔 64px，移动端 32–40px。
- 控件圆角 14px，常规卡片 24px，弹层 28px；移动创作卡片 20px。只有心情标签采用胶囊形。
- 主按钮和播放器按钮至少 48px 高；其余可点击区域至少 44×44px。视觉图标可以 16–20px，但触控区域不能跟着缩小。
- 主输入卡片阴影 `0 8px 32px rgb(32 34 31 / 6%)`；其余页面主要靠间距和底色区分。作品列表不套多层卡片。
- 页面背景不加全屏纹理、噪点、持续模糊或透明玻璃层。品牌插画可以有静态柔影；Logo 母版本身无阴影。
- 图标统一一套 20px / 1.75px 线宽系统；操作必须有可访问名称。不要混用 emoji、实心图标和多种描边风格。

## 4. 页面结构与响应式规则

内容最大宽度 1200px，外容器最大宽度 1248px（包含左右各 24px 内边距）。移动端左右各 20px，320px 极窄屏可降至 16px。

| 宽度 | 布局 |
|---|---|
| ≥1024px | 创作区左右双栏，比例约 1.25:0.9，间隔 64–80px；作品库三列 |
| 768–1023px | 双栏间隔 32px，标题 48px；空间不足时表单按钮另起整行 |
| ≤767px | 单栏；文案 → 创作框 → 品牌小插画；作品库一列，封面最大 360px |
| ≤360px | 允许按钮组、导航和标签换行；保留关键名称，不制造横向页面滚动 |

顶部导航桌面 88px、移动 72px。首版导航保留「创作」「我的作品」；账户入口承载额度、支付与设置。移动端顶部也必须保留可访问的账户入口，可用 44px 图标按钮收入菜单；预览只示意入口，实际菜单还需实现。

UI-01 / 03 / 04 / 06 已有随包界面预览；其他页面提供的是实施规范，需要在实际产品中完成并验收。预览里的示例次数和示例作品不构成正式定价、权益或生成承诺。

### 4.1 状态文案与真实业务状态

| 后端状态 | 用户看到什么 | 允许的下一步 |
|---|---|---|
| VALIDATING / RESERVED | 正在确认这次创作 | 不重复提交；显示本次消耗依据 |
| QUEUED | 已加入队列 | 可以离开，任务保持可追踪 |
| SUBMITTED / PROCESSING | 正在生成你的音乐 | 展示状态，允许回作品库 |
| UNKNOWN | 正在确认生成状态 | 保留原任务；后台核对，不自动新建付费任务 |
| DELIVERED + 音频可访问 | 已完成，可以试听 | 播放、下载、查看使用条件 |
| DELIVERED + 音频暂不可访问 | 音频加载遇到问题 | 重新加载当前音频，不重新生成或再次扣费 |
| FAILED | 这次没有完成 | 展示服务端确认的扣费 / 退回情况，再提供明确重试动作 |
| REJECTED | 请调整这段描述 | 提供可操作原因，保留原文 |
| CANCELLED | 已取消 | 扣费或释放信息以账本为准 |

「再做一个版本」属于新一次生成，提交前必须重新显示次数消耗。「重新加载音频」是读取现有结果，界面和含义必须区分。

### 4.2 组件状态

- 按钮：default / hover / pressed / focus-visible / disabled / busy 都有定义。busy 保持原尺寸，显示动作名或明确状态，并阻止重复提交。
- 文字输入：标签始终可见；placeholder 只作例子；错误说明位于字段下且与字段关联。不要仅把边框改红。
- 心情标签：未选为描边，选中为墨黑底白字，并维护 `aria-pressed`。不能通过颜色代替选中语义。
- Toast：只用于可忽略的短反馈，建议 4 秒；错误、支付和授权条件不能只出现为短暂 Toast。
- 模态框：桌面宽不超过 560px；移动端可作底部面板，最大高度 `min(85dvh, 760px)`，内部滚动；背景不可滚动，焦点进入并限制在弹层，关闭后回原触发按钮，Esc 可关闭非强制步骤。
- 粘性播放器若启用：只在用户开始播放后出现；底部预留其实际高度与 safe-area，不遮挡最后一张作品或支付按钮。移动端软键盘出现时不压缩正文为不可用区域。

## 5. 动效规格：把“轻盈”写成可测试参数

缓动常量：`ease-out = cubic-bezier(.22,1,.36,1)`；`ease-ui = cubic-bezier(.2,.8,.2,1)`。默认只动画 `transform` 和 `opacity`；颜色过渡用于小组件，不动画整页阴影、模糊半径、宽高或滤镜。

| ID / 场景 | 触发、起止值 | 时长与缓动 | 次数、停止条件 | 减少动态时 |
|---|---|---|---|---|
| MOT-01 页面内容入场 | 路由内容就绪；opacity 0→1，Y 12→0px | 480ms，ease-out | 一次；不等待动画完成才允许交互，不重播已在阅读的内容 | 立即显示最终态 |
| MOT-02 首屏花瓣舒展 | 首次进入首屏；Y 18→0px，旋转 -16→-10°，opacity 0→1 | 720ms，ease-out | 每会话一次；回导航不重播；加载失败显示静态符号 | 静态最终态 |
| MOT-03 主按钮按压 | pointerdown / keydown；scale 1→.98 | 100ms，ease-ui | pointerup / keyup / cancel 后 100ms 复原；不移动周围布局 | 无缩放，以状态样式反馈 |
| MOT-04 标签选择 | 用户选定；背景透明→ink，文字 ink→白 | 160ms，ease-ui | 单次；重复点当前选项不闪烁 | 即时切换 |
| MOT-05 作品悬停 | 仅支持精细指针；封面 Y 0→-3px | 160ms，ease-ui | 离开恢复；触屏没有粘连 hover；键盘无需 hover 可完成操作 | 不位移 |
| MOT-06 等待时的微风 | 真实进入等待阶段；Y 0→-6→0px，旋转 -2→2→-2° | 一轮 2400ms，ease-in-out | 最多两轮，总 4.8 秒后静止；同任务阶段变更不重新启动；离屏或隐藏标签页暂停 | 静态符号 + 完整状态文字 |
| MOT-07 生成完成 | 当前任务首次拿到可用结果；封面图 opacity 0→1，scale .96→1，旋转 -19→-15° | 520ms，ease-out | 一次；回访已完成作品不庆祝重播，不伴随自动音效 | 立即展示结果 |
| MOT-08 面板开合 | 下载 / 购买面板；opacity 0→1，Y 12→0px；遮罩 opacity 0→1 | 打开 240ms，关闭 160ms，ease-ui | 一次；焦点管理与遮罩同步；连续操作不堆叠多层 | 即时开合 |
| MOT-09 播放反馈 | 用户主动播放；进度位置 = currentTime / duration | 播放期间随真实时间更新；可见页面最多约 30 次 / 秒 | pause / ended / error 停止；隐藏页停止视觉更新，回来立即与音频时间同步；不自行暂停用户已开始的背景音频 | 保留静态波形与功能性播放进度，关闭装饰脉动 |
| MOT-10 加载占位 | 数据尚未可用，预计超过 300ms | 立即展示静态、同尺寸占位块 | 数据就绪移除；不使用循环扫光；短于 300ms 的操作无需闪现骨架屏 | 相同 |
| MOT-11 局部提示 | 成功保存等非关键反馈；opacity 0→1，Y 4→0px | 160ms，ease-ui | 单次，通常 4 秒退出；鼠标悬停或键盘聚焦时不消失 | 即时显隐 |

禁止为所谓“高级感”增加弹簧过冲、文字打字机、强制鼠标跟随、滚动视差或连续自动跳动的 Logo。未来加入新动效，必须补齐本表的触发、幅度、时长、次数、停止条件和低动态替代。

`prefers-reduced-motion: reduce` 必须在首次渲染前生效，也响应运行中的系统变更。站内设置如提供「减少动态」，只可进一步减少，不覆盖系统要求。非必要运动关闭后仍完整展示状态、错误和成功信息。参考：[W3C 交互触发动画说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。这是本产品主动采用的设计要求，不声称仅凭这一项就满足完整无障碍标准。

### 5.1 音频与视觉的特别约束

- 默认无声音。创建成功、切换作品、页面恢复可见均不自动开始播放；只有明确用户播放动作可以发声。
- 波形数据来自当前音频的解码或服务端采样，不能用随机柱形冒充音频内容。波形未就绪时显示「波形加载中」或简单进度轨道，音频本身可播放时不要阻塞试听。
- 初次加载显示真实 duration，未拿到时长前用占位；时长数字不依靠 animation 虚构。拖动 seek 时显示目标时间，结束拖动后以播放器实际结果校正。
- 装饰花瓣不随着随机数跳动。以后做音频响应视觉时只能读取实际分析数据，并提供静态替代；不列为首版必做。
- 播放、暂停、音量、拖动、下载必须有可理解的标签；不能靠记忆图标操作。整张作品卡不是嵌套多个按钮的大按钮。

## 6. 文案、语言和移动端细节

- 日本首发使用完整日语界面。开发验收可用随包中文版，但上线前必须检查日语扩展文案、错误、支付、邮件和使用条件；不要混入未翻译的英文状态常量。
- 英文不强行全大写，只有简短装饰性编号例外。长标题最多两行，完整名称在详情可读；关键金额、到期时间、扣费结果和错误不得省略。
- 单位统一：时长显示 `00:30`，明确「纯音乐」。额度叫「生成次数」或经业务确认的统一名称，不叫 Token。
- 不在消费者操作流程中展示 EKS、RDS、TokenStars 路由、模型 Token 数等实现细节。模型选择若无明确消费者收益，不占首版主界面。
- 创作草稿在登录、暂时离开、可恢复的网络错误后仍能恢复；敏感提示词的保存遵循项目现有隐私规则，不在前端擅自无限期保留。
- 320px 屏、200% 文本放大下内容仍可读，输入和按钮不能被底部工具栏遮挡。移动浏览器动态地址栏用 `dvh` 与 safe-area 处理，不写死屏幕高度。
- 重要任务状态用 `aria-live=polite`；阻断错误用字段关联或 `role=alert`。播放时间不每帧向屏幕阅读器播报。

## 7. 实施优先级与交付边界

**P0：** 标志与 token、创作 / 等待 / 结果 / 作品库、登录和支付必要状态、下载与使用条件、响应式、键盘可达、减少动态、真实业务状态。

**P1：** 封面系列扩展、可分享的作品卡片、可关闭的音频响应视觉。分享必须遵守项目既定公开内容与授权范围；未完成相应能力时不要先出现「发布」按钮。

首版不以浏览量、点赞数、虚构社区或装饰动画的数量作为验收目标。品牌设计只能形成体验假设；它是否受欢迎要通过真实用户验证。后续记录「开始输入 → 首次提交 → 完成后主动试听 → 导出 → 再次创作」，用漏斗和访谈检查界面，不编造增长承诺。

技术接入保持现有约定：AWS EKS / RDS / ALB / S3；文本能力由 TokenStars 的 GPT 优先提供；音乐由已获授权、条款明确的音乐服务产生；Stripe 处理卡支付。此包只定义品牌和前端体验，不重新决定供应商或商业价格。
