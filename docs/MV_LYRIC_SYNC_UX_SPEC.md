# 照片 MV 与歌词同步体验：建议规格

状态：**待产品审阅的交接稿，尚未实现**。2026-11-25；源码核实于 PR #122 `1d27353705538a7c55adcf55918fc710b443b4c4`。本稿不授权生产部署、DGX 更新、外部付费请求或新增收费。

## 要解决的体验

产品负责人反馈：照片 MV 是优先路径，封面直出应排在后面；歌词校准入口与实际歌词距离远；调整后缺少即时、可理解的试听反馈，希望有时间轴／游标并尽量自动对齐。

目标：用户在同一工作区完成选照片、检查歌词同步、导出；绝大多数用户不必手动逐句校准。PDF 仅帮助定位布局困扰，不能证明某首歌的实际对齐来源或声音是否同步；用户附件、歌曲内容和线上截图不进入公开仓库。

## 已有实现：先复用与诊断

- `PhotoVideo.tsx` 已有统一长度选择、封面／照片两种生成、结果预览／下载；目前封面在照片前。
- `SyncedLyrics.tsx` 已有播放器真实时间、点击歌词 seek、整首 ±0.5 秒、播放时“这句从现在开始”、未保存草稿及保存／撤销。
- `SongDetail.tsx` 的视频卡通过滚动到下方歌词区打开工具；校准不是在视频区就地完成。
- `docs/LYRIC_ALIGNMENT.md`、`apps/worker/src/pipeline.ts`、`packages/providers/src/alignment/` 与 `deploy/dgx/music/server/{align,forced}.py` 已有自动对齐路径：分离人声后 forced alignment，必要时 Whisper 回退；失败可降级到 estimated。代码存在不等于当前 DGX 已部署、健康或该首歌词已准确对齐。
- 已有后台批量重对齐；面向普通用户的单首“重新自动校准”需要独立设计，不能直接开放后台批处理权限。

## 第一阶段：把手工调整变得可理解

### 1. 照片优先

- 视频区先展示“上传照片做 MV”，权利确认保留在文件选择前，沿用 3–10 张及现有长度选项。
- “不上传照片，用歌曲封面做视频”放在下方，作为次级入口／折叠区。仅打开工作区不应触发上传或编码。
- 两条路径共用一个结果区；切换不能静默清空用户已选照片、校准草稿或已生成文件。清除时明确提示。
- 照片功能关闭时清楚说明暂停，保留可用的封面路径；游客继续保留注册认领前提，不放开权限。

### 2. 一个歌词同步工作区

- 视频区附近提供“检查歌词同步”，打开就地工作区（手机可用全屏面板）。里面同时可见歌词、播放／暂停、当前时间、时间轴和小预览，不再只跳到远处歌词区。
- 同一首歌只有一个音频时钟；视频区与歌曲歌词区共享同一份时间数据和未保存状态，不创建两个独立播放器。
- 选中一句时高亮歌词与该句时间块；点击时间轴可以定位，能从该句前约 2 秒试听，并循环当前句及短前后文。
- 用实际音频计算简化波形，显示当前播放游标和歌词起止标记；可缩放当前片段。混音波形只表示声音能量，不能冒充人声起点或自动证明歌词正确。
- 波形读取失败时保留时间刻度、游标和文字调整；不阻断播放或导出。只使用当前用户有权限读取的音频，不新增公开媒体链接。

### 3. 操作与反馈

- 用用户的判断表达按钮：“歌词出现太早 → 晚一点”“歌词出现太晚 → 早一点”，同时显示实际秒数；细调默认 0.1 秒，保留更大步进。
- 明确区分“整首一起移动”和“只调这一句”。拖动句子时间块只改所选句，展示范围约束；不得悄悄推乱其他已校正句。
- 本地修改立即更新高亮和小预览，无须每次重新请求整支 MP4；提供撤销、恢复、保存，以及清楚的未保存状态。
- 保存后重载验证：歌曲页、LRC、封面视频和照片 MV 使用同一份保存时间。编辑后既有 MP4 不会自动改变，应提示重新生成，避免把旧文件当成新校准结果。
- 调整时间不重新生成歌曲、不消耗歌曲生成额度。生成 MP4 失败也不能丢失已选照片或校准草稿。

## 第二阶段：可靠的自动对齐优先

先核实已有能力：

1. 在有权查看的运行环境核实歌曲 timing source（estimated / aligned / corrected）、DGX 当前版本与 aligner 健康、使用的 adapter 和失败／低覆盖／超时日志。不要把前端上线当作 DGX 模型已更新。
2. 用有权使用的中、日、英演唱样本测量行首／行尾误差；包含长前奏、间奏、重复副歌、慢唱及中英混唱。纯音乐不显示歌词校准。
3. 先把结果分成“全曲固定偏移”和“逐句漂移／漏句”，分别验证手工平移与模型重对齐。阈值及语言表现以样本实测制定，不只看 coverage 就宣称同步准确。

然后设计单首“自动校准”：

- 复用既有人声分离＋已知歌词强制对齐，先生成可试听的新版本，用户确认后应用；不要用通用文本大模型猜时间，也不修改用户歌词。
- 提供排队／处理中／成功／需检查／失败状态。失败仍能播放和制作，并保留原时间；低置信度或缺唱的句子明确标出，不把估算结果伪装成模型对齐。
- 请求须验证所有者、限次、幂等和单首并发；异步任务完成时检查歌词／音频／时间版本。不能覆盖用户在等待期间保存的手工校正，也不能把旧版结果写回新歌词。
- 用户实际采用的时间版本必须用于后续两种视频及 LRC。缓存按音频和歌词版本区分；试听、刷新、重复点按钮不应重复计费。
- 不让后台批量重对齐与用户生成任务争抢资源而无排队提示；评估既有 GPU 队列及优先级，再开放用户入口。

## 成本与外部服务

先测已有 DGX 对齐的耗时、失败率和边际成本，再对比外部服务在演唱、中日英上的质量。自动识别语音有时间戳不等于对演唱歌词可靠，不能只按每分钟报价选供应商。

建议基础对齐随歌曲提供；修复平台原有同步失败不应默认再收一次歌曲额度。若有额外高精度付费选项，先给出明确价格与用户确认，失败不收费或自动返还；不因用户表达“愿意花钱”就启用实际扣款。本轮不实现收费。

外部方案只需音频与歌词，不需要照片、账号资料或订单；启用前核实其处理地点、留存／训练条款及隐私披露。不得把照片或其他无关用户数据随请求发送。
