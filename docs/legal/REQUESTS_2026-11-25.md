## 一、DGX 作曲服务器：保存期限从 30 天改为 6 天

**交给**：管理 DGX 的同事 · **耗时**：约 2 分钟 · **影响**：作曲服务重启约 1 分钟，期间正在生成的歌会自动重试，用户额度不会白扣。建议在深夜等无人使用时执行。

**为什么**：免注册试做承诺「7 天后连同输入一起删除」。作曲服务器上存有用户描述、歌词和音频的一份副本，保存期限设为 6 天，加上每小时一次的清理，合计在 7 天以内。2026-11-24 重新部署后，这台机器上是 30 天。

**步骤**（在 DGX 上依次执行）：

```bash
cd ~/yuha-spark
grep RETENTION_DAYS .env          # 看现在的值，应该是 30
sed -i 's/^RETENTION_DAYS=.*/RETENTION_DAYS=6/' .env
grep -q '^RETENTION_DAYS=' .env || echo 'RETENTION_DAYS=6' >> .env
grep RETENTION_DAYS .env          # 确认是 RETENTION_DAYS=6
docker compose up -d music        # 只重启作曲服务，不需要重新构建
```

**确认生效**（请把以下两条命令的输出发回）：

```bash
docker exec yuha-music printenv RETENTION_DAYS      # 应输出 6
docker logs --since 5m yuha-music 2>&1 | grep -i retention
```

第二条命令的输出可能是以下两种之一，都正常：

- `retention: removed N jobs older than 6 days`：6 天前的旧任务已被清掉。
- 没有输出：没有过期任务。

**出问题时**：把 `.env` 改回原来的值，再执行 `docker compose up -d music` 即可恢复。
