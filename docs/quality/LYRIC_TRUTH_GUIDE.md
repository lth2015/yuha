# 员工测试歌曲的歌词标注指南

这份指南给帮忙做"标准答案"的员工看。你们在产品外标注的时间轴，会用来判断哪种自动对齐方案最准（Whisper、Qwen，或两者加权平均），评分方法见 [LYRIC_BENCH.md](LYRIC_BENCH.md)。**标准答案准不准，直接决定最后选哪种方案**，所以请认真听，不要图快。

## 做哪些歌

- **18 首**：中文、日语、英语各 6 首。
- **用员工账号**在 `/create` 生成，选"有人声"，**自己填歌词**，时长 2 分钟。员工账号做的歌才会被导出，用户的歌不会。
- 每种语言的 6 首里，尽量包含这些情况：
  - 副歌重复两遍以上；
  - 中间有间奏（几秒没人唱）；
  - 有唱得很快、字很密的一句；
  - 有拖得很长的一句；
  - 生成出来以后，如果发现歌手**漏唱或改唱**了某一句，记下来（见最后一节）。
- **时间限制**：DGX 只保留最近 6 天的音频。做完歌后请在 **6 天内**完成校准并通知负责人导出，超过就要重做。

## 如何标注

1. 把员工测试歌曲下载到本机，用能查看毫秒时间的音频工具独立听。关闭播放器上的同步歌词，避免被模型结果影响。
2. 按歌词的行顺序从 0 开始编号，跳过空行和段落标签。记录每句第一个字实际唱出的秒数。重唱的副歌逐次标注。
3. 漏唱、明显改唱或被即兴演唱取代的行保留编号，写 `"sung": false, "start": null`。
4. 写入 `annotations/<标注员>/<歌曲ID>.json`，格式见 [LYRIC_BENCH.md](LYRIC_BENCH.md)。两人各自标注后再比较时间差。
5. 把标注和员工测试歌曲清单交给负责人。清单的 `songs.json` 包含歌曲 ID、DGX 作曲任务 ID、语言和歌词。用 git 忽略的基准目录保存，用户歌曲和音频不进入仓库。
