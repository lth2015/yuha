# YUHA iOS App · 完整开发任务书（Codex 执行版）

> 2026-10-25。目标：在**不重写现有后端、不复制积分账本、不影响 yuha.studio Web 业务**的前提下，发布日本区 iOS App。本文是待实施任务，不代表功能已完成或通过 Apple 审核。
>
> **当前仓库依据**：`apps/web` React 18 + Vite SPA；`apps/api` Fastify；`apps/worker` 异步音乐任务；`packages/contracts` 共享协议；`packages/db` MySQL 积分账本；`packages/providers` 音乐、存储、支付适配；`infra` AWS。参考 README、docs/DEVELOPMENT.md、docs/OPEN_ITEMS.md、docs/LAUNCH_READINESS.md。仓库中部分状态文档与实际线上进展可能不一致，**先核验现状再修改**。yuha.studio 的商业运营主体与 NETX 开源仓库管理主体分离，不能把个人经营资料写入公共仓库。

## 0. 产品目标与不可变约束

- App 名称：**YUHA**；定位「用一句话，生成属于你的音乐」。首发日本 App Store；界面保持日本語 / 中文 / English。
- 用户主流程：登录 → 描述情绪/场景 → 选择人声、风格、时长/歌词 → 提交生成 → 查看异步进度 → 播放成品 → 私人曲库 → 下载/分享。真实音乐生成仍由已有后端 Worker 执行，iPhone 不运行生成模型。
- 复用同一用户 ID、歌曲 ID、订单/积分账本、权益记录、内容授权与服务端权限控制；Web 与 iOS 可跨端查看已购权益与作品，不得产生双账本或客户端自行加积分。
- iOS 支持数字商品付费是正式路线，但**任何定价、商品包、订阅条款、退款政策的实际启用都须经营者另行批准**。
- 开发使用 Capacitor 包装现有 React/Vite，按需使用原生插件；若核心播放器、后台音频或审核体验无法达标，评估局部 Swift 原生模块，不重写全站。
- 个人 Apple Developer 账号可同时发布 YUHA 与 WonderLab；Bundle ID、App Store Connect 应用记录、IAP 商品和品牌资料分别管理。
- 发布范围默认日本，扩区须评估隐私、trader、支付、版权和税务；不要假定日本区完全无需公开联系信息。

3. 核实 `docs/LAUNCH_READINESS.md` 和 `docs/OPEN_ITEMS.md` 的陈旧描述：不能把历史「未上线」「模拟音频」等结论当作当前生产事实；对真实生产状态无法访问时标记「待运营者核实」。
4. 盘点 WebView 对音频播放、录制、文件下载、OAuth 重定向、第三方 Cookie、WebAuthn、深链和系统分享的限制，给出兼容性与替代方案。

## 2. IOS-YUHA-02 · iOS 工程与平台适配

1. 在 monorepo 中加入版本锁定的 Capacitor 与 iOS 工程；独立的 `ios` 构建入口和环境配置，Web 构建不受影响。
2. 使用生产 API 的 HTTPS 端点；开发/预发/生产分离。不得把 API secret、Stripe secret、AWS AK/SK、模型密钥、管理员令牌写入 iOS 包。
3. 配置 Bundle ID（最终由 Apple 账号确认）、App 图标、启动屏、版本号/build number、Universal Links、Associated Domains、ATS、安全区和状态栏。
4. 保留现有多语言；适配 iPhone 竖屏、Dynamic Island、键盘、刘海、Home Indicator、深色模式、字号和 VoiceOver。
5. 生成可复现的 `pnpm` 构建与 Xcode 打包文档；CI 运行 Web 回归和 iOS 静态构建检查，真机测试单列。

**验收**：iOS 模拟器可启动、登录页/首页/曲库导航正常；Web 的 build/typecheck/test 不回归。

## 3. IOS-YUHA-03 · 身份认证与账号生命周期

1. 复用生产身份提供商及服务端会话，使用 iOS 安全的 OAuth Authorization Code + PKCE、系统浏览器认证会话/回调，不在内嵌 WebView 直接收集第三方密码。
2. 现有 Google 登录若在 iOS 保留，评估并按 Apple 适用要求提供 **Sign in with Apple** 或合规等效选项；Apple 私密转发邮箱须可用于账户映射、通知和恢复。
3. Apple/Google/Web 登录绑定同一账户需明确规则：邮箱相同不自动合并未验证身份，防止账号接管；设计安全绑定/解绑、会话撤销和注销。
4. Token 仅存系统安全存储（Keychain 等）；不把长期 token 放在 localStorage；处理 token 刷新、锁屏、后台恢复和多设备退出。
5. 支持 App 内发起**账号删除**及相关数据保留/不可删除法定义务说明；不是仅提供「退出登录」或「停用账号」。
6. 管理/客服后台不进入消费者 iOS 导航，相关权限始终由 API 鉴权。

**验收**：新用户/老用户登录、Google/Apple 绑定、注销、删除账号、失效令牌、异常回调及多设备会话测试通过。

## 4. IOS-YUHA-04 · 创作、任务与曲库

1. 复用 `packages/contracts` 与 API：文本描述、风格、长度、人声/纯音乐、用户歌词、语言及内容安全校验与 Web 一致。
2. 创建任务必须由后端完成积分预留/扣减/失败返还；禁止客户端计算余额或重复提交；增加 idempotency key 防止双击、断网重试重复扣费。
3. iOS 前台轮询/订阅进度；后台期间任务继续在服务器执行；恢复后通过 API 恢复任务状态，**不得假设 iOS 后台可以无限执行轮询**。
4. 私人曲库支持分页、搜索、封面、状态、失败重试、作品删除和可控分享；所有歌曲资源使用授权校验与短期有效 URL。
5. 显示模型来源/使用权、可下载格式、版权提示；不得把尚未确认的商业版权保证写成无条件承诺。

**验收**：生成成功/失败/超时/重试、跨端同步、余额并发一致性、权限越权与签名链接过期均有测试。

## 5. IOS-YUHA-05 · 原生音频播放器、下载与分享

1. 实现适合 iPhone 的播放器：播放/暂停/进度/切歌、锁屏与控制中心媒体控制、耳机和蓝牙、音频中断恢复；按产品需求评估后台音频能力与对应 entitlement。
2. 使用 AVAudioSession 等原生能力或稳定插件，避免仅依赖 WKWebView 音频在锁屏/后台时的表现。
3. MP3（及后端确实支持且合法交付的格式）可下载至 Files、系统分享；本地离线保存如启用，明确容量、清理、版权与退出登录策略。
4. 系统分享采用原生 Share Sheet；用户取消分享不视为成功；不能把私有带鉴权的短效下载 URL 当作永久公开分享链接。
5. 文件名、封面、ID3 元数据、中文/日文字符、下载失败/网络中断和磁盘空间不足要有兜底。

**验收**：真机锁屏播放、蓝牙切换、电话中断、文件保存、分享、长音频、弱网及不同 iOS 版本测试通过。

## 6. IOS-YUHA-06 · StoreKit 2 / 商业化（核心）

**原则：iOS 内数字音乐生成积分、订阅和功能权益，默认按 Apple IAP 规则设计；不得将现有 Web Stripe Checkout 或稳定币支付原样嵌入 App，也不得通过隐藏按钮、WebView 或文案规避审核。** 日本存在特定替代支付/外链制度，是否适用及其条件须按上架时最新 Apple 日本区条款专项评估；未经批准先以 StoreKit 2 为基线。

1. 在服务端建立平台无关商品目录与权益映射：`apple_product_id` ↔ SKU ↔ 积分数量/订阅权益/有效期；明确 DROP/CREATOR/STUDIO 与现有生产定价的关系，**先核对真实现行商品，禁止凭历史 README 推定价格**。
2. 设计 App Store Connect 商品类型：消耗型积分包、自动续订订阅（若业务需要）；是否允许多次购买、结转、到期、退款、取消与跨端使用，必须先确认规则及日本预付式支付手段等合规问题。
3. 客户端使用 StoreKit 2 购买；**服务端验证 Apple 签名交易**并处理 App Store Server Notifications V2；以 Apple transaction ID / original transaction ID 做唯一约束与幂等入账。
4. **统一积分账本**：Stripe 订单与 Apple 交易进入同一 ledger，不可重复入账；处理恢复购买、退款、撤销、订阅续费、账单重试、宽限期、退款后余额已消费等异常。
5. 购买页显示商品真实价格、币种、自动续订条款、取消方式、服务条款、隐私政策和恢复购买入口；对既有 Web 订阅用户的 iOS 权益访问制定明确政策。
6. Apple 购买凭据不等于客户端可信积分；所有权益由后端判断。不得将 Stripe API secret、Apple 私钥或通知验证密钥嵌入 App。
7. 明确支付开关：开发阶段 StoreKit 本地配置和 Sandbox；上线前需运营者确认商品、费率、Apple Small Business Program 资格（如适用）、税务与法律材料。**未经确认不启用真实收费**。
8. 预留 Apple 订阅管理与用户退款请求的标准入口；运营后台可审计跨渠道交易与异常冲正。

**验收**：沙盒购买成功、重复通知、通知乱序、退款、撤销、订阅续费/取消/恢复、跨端积分同步、重复点击、网络断开、账号切换、恶意重放均通过；任何异常不造成双重发放积分。

## 7. IOS-YUHA-07 · 安全、隐私与成本防滥用

- API 继续强制用户鉴权、配额、限流、内容审查、费用预算和任务并发上限；移动 App 可被逆向，**不能以隐藏按钮或设备 ID 作为安全边界**。
- 需要设备真实性时评估 App Attest，但不能把它当成绝对防刷或唯一设备身份；设备信号须与账户、服务端限额组合。
- App Privacy、第三方 SDK 隐私清单、数据保留、删除、崩溃日志、AI 输入/歌词传输、跨境处理、APPI 说明与实际数据流一致。
- 最小化权限；不因普通音乐创作索取相册/麦克风/通讯录权限；如需音频录入另行设计并解释用途。
- 服务端生成成本、下载带宽、存储、IAP 佣金和退款风险纳入单位经济模型；给出每用户/每日和全站熔断策略。

## 8. IOS-YUHA-08 · 日本区 App Store 上架

- 开发者身份：日本个人开发者，显示真实法定姓名；不将身份证、住址、电话、支付卡或签名材料提交到 GitHub。
- 初次销售地区仅日本；核对日本适用的交易者联系信息、特定商取引法、消费税、订阅披露、版权、AI 生成内容及 Apple 审核政策。欧盟未来单独评估。
- App Store Connect：Bundle ID、App 记录、IAP 产品、税务/银行协议、隐私政策 URL、支持 URL、截图、分级、出口合规、版权、审核说明、演示账号（若需要）。
- 审核账号应为受限测试用户，提供可完成核心体验的测试额度；不可暴露管理员权限或生产密钥。
- TestFlight 内测：至少两种真实 iPhone 尺寸、两种 iOS 版本；覆盖新用户、现有 Web 用户、无积分用户、订阅用户、离线、弱网、退款和分享。
- App Store Guideline 4.2：原生播放器、后台音频、文件导出、系统分享等构成实际 App 价值，不能只把网站套壳。
- 品牌/服务条款/模型权利：核实 YUHA 名称和商标、生成音乐的许可、用户下载与商业使用范围。仓库既有法律状态文档若过期，按现行合同和实际运营事实更新，不能凭代码推断授权。
