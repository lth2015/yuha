2026-11-26 · 产品要求与开发任务 · 仓库基准 `c969ae0`

**歌词同步是有人声歌曲的基本质量。YUHA 负责自动对齐、判断结果是否可靠、自动应用并在失败时恢复。自动流程验收通过后，退役所有用户手动对齐功能。** 波形、播放游标和音轨编辑各自服务听歌与创作。它们的操作不修改歌词时间戳。

下一阶段资源优先给歌曲质量。照片／封面 MV 相应受益，因为它们会使用同一份已核验歌词时间轴。Veo 的新增产品工作仍排在自动歌词同步之后。 [上一轮执行计划](NEXT_ITERATION_MUSIC_FIRST.md) · [Claude 独立评审](https://github.com/lth2015/yuha/pull/147)

#155 合入后，Claude 按 [歌曲页交互与下一批验收](agents/LYRIC_AUTO_SYNC_UX_HANDOFF.md) 开工。线上生效和旧歌补齐仍分别核验。

## 交付给用户的体验

| 情况 | 用户看到什么 | 系统负责什么 |
| --- | --- | --- |
| 新歌就绪 | 直接播放。同步先完成就立即跟唱；还在处理时显示「正在同步歌词」并可先看静态原词 | 歌曲交付后自动开始，尽早达到首播可用。结果通过验证后自动生效，页面刷新后仍可恢复 |
| 已有歌曲 | 已可靠同步的歌正常播放。缺失或估算的歌打开后显示实际处理状态 | 按需读取已交付音频，按容量预算自动补齐。对相同音频和歌词版本去重，刷新和多端播放不会各起一次任务 |
| 有唱错、漏唱或听不清的行 | 原词仍可看，可信部分可以跟唱。疑问行在播放时不错误高亮，字幕也跳过。确有需要时说明「部分歌词暂未同步」 | 依据人声和时间证据区分未确认、漏唱／改唱与已对齐。保留用户原词和原音频，禁止虚构缺失时间戳。把不完整交付计入质量缺口 |
| 自动同步失败 | 可以继续听歌、看静态歌词、导出无字幕视频。歌词区可提供一次「重新自动同步」动作 | 后台先做有界重试或经过验证的候选补算。重试由系统应用结果。服务恢复后可补处理，避免长时间假装「正在同步」。已有可信结果继续可用 |
| 自动结果应用时正在播放 | 高亮跟上当前位置，音频不停顿。播放波形仍能拖到任意位置 | 更新歌词视图时保留播放器时钟与歌曲身份。仅切换对当前音轨和歌词有效的版本 |
| 导出视频或歌词 | 播放和导出使用同一版本。已经保存的文件仍能播放 | 导出启动时绑定所用时间轴，结果稍后改变时可重新导出。不将估算、缺唱或不可靠部分伪装成已同步字幕 |

重新自动同步是异常时的可选操作。普通新歌和需要补齐的旧歌必须在没有任何手动对齐、确认、保存或主动重试的情况下参加验收。纯音乐没有歌词同步任务和同步状态。写词、歌词文本协作与音轨编辑继续按各自功能演进。

| L3 把质量测出来 | 用已有授权测试音频测当前基线。给可复现的标注格式、配对统计和计费／耗时汇总 | 两位评测者盲听，核对分歧和留出样本。对中、日、英分别复核，不用报告平均值掩盖语言退步 | 可与 L2 并行，结果供自动交付和模型选择。生产用户无需参与标注 |
| L4 自动交付与异常恢复 | 自动入队、去重、限额、音轨与歌词版本校验、自动保存、客户端读状态。先覆盖新歌，再给缺失／估算旧歌受控补齐；尊重已有校准版本 | 设计状态和可选自动重试。用手机与桌面从歌曲页正常入口完成首播、刷新、跳播、并行打开和导出验证 | 有已测的任务时限、容量和恢复办法后小范围上线。按质量门槛扩大。旧编辑器不是此批验收路径 |
| L5 模型补强 | 若准确度、覆盖或首播就绪仍达不到门槛，同批比较现有路径、付费音频候选和疑难段补算。有必要也比较全曲付费 | 复核实际提升、成本、等待、故障回退及数据说明，再决定接入范围 | 可提前准备候选。实测闭合成本与数据路径后再接入。用户愿意投入资金节省人工时间，模型选择取决于歌声实测 |
| L6 退役手动对齐 | 按下方清单切掉所有入口和人工时间写入，分开发布 UI 切换与最终接口清理 | 核对旧版、三语、所有权、视频入口及故障情况都无法进入人工校准。验证历史已校准的歌曲仍正常 | L4 达标且生产小范围数据通过后执行。若 L5 对达标必要，先完成 L5。退役后回退走可信旧时间轴或静态歌词 |

这阶段优先交付 L1、L2／L3 和 L4。L6 可以先盘点与准备实现，生产切换取决于自动能力。Claude 负责实现、检查、发布跟进。Codex 负责产品和交互，独立验收结果。 [仓库协作约定](agents/CODEX_COLLABORATION.md)

## 手动对齐退役清单

当前基准已确认两处用户入口，分别在歌词区和做视频区。Claude 开工时还需搜索移动入口、深链接和近期合入的分支，列实际调用者。生产退役包括以下能力：

- **歌词及视频入口的所有人工时间写入。** 从 `SongDetail`、`SyncedLyrics`、`PhotoVideo` 和 `LyricSyncStudio` 的现有路径移除单行拖动、打点、整体偏移、输入时间、微调按钮、歌词时间草稿、仅用于时间编辑的撤销／重做、接受提案后手动保存，以及「先保存校准再导出」的阻拦。清理三语提示、深链接、相关样式及审计用例。若有可复用的波形／游标，只保留媒体播放与音轨操作用途。
- **旧客户端的人工写入。** 审计 `POST /v1/tracks/:id/lyric-timings` 的客户端调用。切换期给旧标签页明确的更新提示，避免写到新系统的自动结果。确认部署版本与客户端兼容后退役人工写入语义。现有 `lyric-proposal` 可复用去重或任务代码，新流程的正常结束是系统应用结果，不是给前端一个待手工保存的草稿。
- **历史记录和共用功能。** 已保存的 `corrected` 记录、音频、歌词和已导出视频继续可读；迁移期保留来源及校准保护。回退时优先使用匹配音频版本且可靠的历史时间轴。保留歌词与 LRC 的合规读取、播放跳转、自动重算和运营排障能力。清掉无调用方的手动编辑端代码时检查复用的导出函数，避免顺带删掉时间轴消费者。

## 达标与上线顺序

1. **先固定验收前提。** 以同一批中日英音频建立基线和留出集。记录每种语言的整首零操作可用率、首播就绪率、处理时延、逐行匹配、未唱却高亮和恢复成功率。对齐中的歌曲、静态降级、自动重试仍失败、无可靠结果都单列；不能用隐藏疑问行做出更好看的整体成功率。由双方在看候选留出成绩前用基线确认绝对质量线和样本量。
2. **先上线可验证的自动流程。** 完成新歌、受控旧歌、超时、重复副歌、漏唱、播放器和字幕一致性、版本竞争的行为测试。小范围线上核对真实歌声，中、日、英分别达标再扩大。任何未达标继续修复或比较付费方案。无数据支持的等待时长不放进产品承诺。
3. **再退役人工入口和写入。** 自动流程通过后，先切用户入口，核验现有时间轴、旧标签页的明确提示和导出体验。随后停用遗留写入并清理实质功能；验收确认当前页面、老链接及直接请求均无法触发人工写入。退役后的线上故障回退到可信版本或静态歌词，故障由平台继续处理。人工编辑不充当恢复方案。
4. **各批及时更新生产和回执。** Claude 在 CI 和交叉验收通过后按现行发布流程推进到 `yuha.studio`，记录 PR、部署链接、生产 build SHA、JST 时间、覆盖范围、实际验证与回退状态。涉及 DGX 时同时核验对齐器版本与实测请求。Codex 用正常用户入口复验，线上结果未确认的批次保留为待验证。

### L4b 交叉评审补充

根据 Claude 提出的旧歌方案，采纳仅所有者打开歌曲时触发、只补缺失或估算时间轴、每天限额、新歌优先及员工试用。核对基准为主干 `12d1434` 和 [#155](https://github.com/lth2015/yuha/pull/155) 的 `80c963b`。L1–L3 已合入主干，L4a 尚未合入该基准，生产状态另验。

1. **旧歌强制使用已交付母带。** #155 当前 worker 看见 `provider_request_id` 就优先走旧渲染文件。很多旧歌仍有该 ID，临时文件却已经清掉。L4b 必须以补齐任务类型选择 `audio_b64`，即使旧 ID 还在也一样。用「旧 ID 存在、渲染文件已清理」的样本验收。更新 dgxa 后，用授权测试曲目实际验证请求和时间轴质量，再开启员工试用。
2. **限额后的恢复由系统负责。** 每日上限由服务端原子判断。双开标签页和并发请求只创建一份任务，也只消耗一个名额。达到上限当天继续播放与阅读原词，提示「今天暂时无法同步，下次打开会自动再试」。下一预算日以现有运营时区为准，所有者再次打开时自动评估。被限额而未入队的歌不能写成永久失败的任务。到期可执行的新歌排在旧歌前，测试旧歌批量涌入及多个 worker 争抢。已在运行的旧歌允许完成。
3. **回到歌曲页就看到结果。** 所有者打开页面时可由客户端自动发起受保护的单次请求，普通 GET、站内预取、访客和分享链接浏览均保持只读。只在真实有待执行任务时显示「正在同步」，进入后台暂停查状态，回来时刷新。校准通过就更新歌词和导出所用的时间轴，保留当前播放位置。失败使用静态歌词或可信旧版本，给明确状态。可选整首自动重试应受限并复用同一任务记录，无法靠刷新无限重跑。

首个线上验收用一首符合条件的旧歌、一首已校准旧歌和一首新歌。通过正常页面验证自动触发、刷新去重、旧歌实际送入母带、先后次序、限额后的再次自动触发和双端刷新后结果一致。记录开关覆盖、生产 build SHA 与 dgxa 版本。手动对齐退役仍等自动体验达标后单独发布。

本轮交付为产品规划和任务拆分。当前代码、生产行为及模型费用仍以各实施批次实测为准。
