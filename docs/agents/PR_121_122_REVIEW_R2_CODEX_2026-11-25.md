## #121：需要修复

### [中] 自然搜索 referrer 被第一次读取消费，SEO 场景／语言来源未建立

- **现象**：全新无登录浏览器、无 src 和 localStorage 来源，带合成 Google referrer 打开 `/en/birthday.html`。实际 `POST /v1/visits` 有 `path=/birthday`、`refHost=www.google.com`，但没有 source，`yuha.source` 也为空。Bing → `/ja/travel.html` 同样复现，丢失 `seo-travel-ja`。浏览器确实读取到相应 document.referrer；没有向 Google/Bing 发请求，仅在本地请求中设置合成 referrer。
- **应该**：分别得到 `seo-birthday-en` 与 `seo-travel-ja`，后续页、试做、注册按 first-touch 保持；已有广告来源应继续优先，不能被 SEO 或 scene 替换。
- **位置／原因**：`apps/web/src/lib/visits.ts:133–135` 先调用 `externalReferrerHost()`，将 `referrerSent` 设为 true；随后 `captureSource()` 在 `:97` 再调用同一函数，只得到 undefined。因此 helper 的纯函数单测可以通过，实际首次 page-view 路径却无法建立自然搜索来源。无标签 SEO 访客之后点场景制作入口，可能被记成 scene 来源，损失真正的搜索归因。
- **违反的规则**：首次访问已识别为搜索来源，同时却无法建立该搜索的来源标签，两者不应并存。
- **建议**：把初始 referrer 的读取／缓存与“只在首个 page-view 发送 refHost”的状态分开；同一次来源捕获与事件上报复用该值。不要仅交换两个调用顺序，否则可能修复 source 却丢掉 refHost。
- **回归验收**：通过实际 `reportVisit` 入口验证 Google／Bing → 英／日静态页面，断言 refHost 与 source 同时存在、localStorage 保持；再检查后续导航、已有广告来源、无 referrer、非搜索网站及私密路由。不要只调用 `organicSource()`。
- **版本**：#121 上述 head；与 #122 head 的 visits.ts 无差异。
