# YUHA 独立用户旅程验收 · 2026-11-24

## 结论与版本

**本轮未通过完整旅程验收。** 在固定版本发现 1 条阻断路径、8 条易误导或衔接问题；其中草稿清理和再创作歌词工具是 Claude 已申明正在修复的两项，其余为本轮独立发现。布局检查通过不能消除这些流程问题。

- 需求：[Issue #88，YUHA-CL-20261124-010](https://github.com/lth2015/yuha/issues/88#issuecomment-7133998267)。阻断发现已[提前交接](https://github.com/lth2015/yuha/issues/88#issuecomment-7134581251)。
- 验收代码：master **`31b1aee48cf437f639e78e0a419f7d8696ed847c`**，即 #109 合并版本；整个运行期间保持该 SHA。报告分支：`codex/ux-audit-20261124-independent`。
- 环境：独立本地 MySQL schema、独立存储目录；`RUN_MODE=demo`，local 文本规则、合成音乐、模拟支付；访客试做和照片 MV 在此本地环境开启。真实支付能力为关闭。
- 浏览器：独立 Chrome；主要为 **390×844、360×780**，1280×900 抽查；中文主验收，日文账户/语言持久化、英文场景抽查。另执行仓库完整布局检查，覆盖其原有 360/393/768/1280 视口和语言组合。
- 数据：全部为本轮创建或仓库种子的虚构账号、文字、歌曲；照片为既有交付里的虚构 QA 图及原创场景图。截图不含线上用户或后台数据。
- **这是本地旅程验收，不是 yuha.studio 的线上验收，也不是真实 iPhone/Safari 验收。** 没有修改业务代码、支付配置或线上开关，没有合并或部署。

Claude 分支的 `c9d73cb`（草稿）和 `9aa2bf1`（再创作歌词）不在上述 master 中；未将这些未纳入本轮运行的修复判为通过。后续修复必须记录新的 SHA 并重走对应步骤。

交付推送时发现远端同名分支已有另一份 [Linux 独立审计 `e962bcf`](https://github.com/lth2015/yuha/commit/e962bcf)。该分支完整保留，本轮改用上述独立分支，没有覆盖它。两份报告的发现编号分别生成，后续按页面、复现条件和版本核对归并，不能仅按 UX 编号视为同一问题。本报告结论仅来自本轮本机实测，不将另一环境的观察并入已验证数量。

## 工程与视觉检查

- 安装当前锁文件依赖后 `pnpm build` 成功；首次构建缺本地新依赖，执行冻结锁文件安装后解决，未改锁文件，不列产品错误。
- `pnpm check:ui`：**376 page views，0 problems，0 warnings**。这是既有布局/控件几何检查，与上述独立旅程验收分开记。
- 390/360 手机流程与 1280 日英截图做目视检查。现有透明表面、圆角与暖色背景风格一致；本轮主要问题在状态衔接，未发现需要重画素材才能处理的阻断。
- MP3、LRC、两种 MP4 均有实际产物；视频使用 ffprobe 检查封装、编码、尺寸、时长，照片 MV 另抽出片尾目视核对。
- 本 PR 仅报告与证据，不修改运行代码，因此没有新增业务测试、数据库迁移或重复运行全量单元测试。不能将 Claude 其他 PR 的测试数量记成本轮结果。

### 未验证事项

1. **听觉质量和实际同步**：本机无头浏览器中，应用音频及一个独立、未接入应用 Web Audio 的 audio 对照都停止在 0 秒；AudioContext 虽显示 running，时钟也几乎不走。未能建立可用的听觉环境，因此不把此现象列为产品故障，也不把点击「暂停」或成功下载当成播放/同步验收。须在实际设备试听中文、日文、英文的真实模型歌曲，检查漏唱、音色、间奏、拖动和锁屏。
2. 工具自带 Chromium 最初无法加载 MP4 元数据；独立 Chrome 对同一流程成功，产物为 H.264/AAC。未把该环境差异算作照片 MV 缺陷。
3. 线上 build SHA、CDN、真实 OAuth、真实支付/退款/续费、真实 X 卡片缓存、原生分享面板、iPhone Safari 后台音频均未在本轮确认。
4. 订阅取消流程只检查账单入口和无订阅状态；没有创建真实订阅。本地曾有欢迎额度、演示购买及 UI fixture 赠送，余额绝对值不是上线资金数据。
5. 限额配置为便于重复旅程在本地放宽；没有对线上做容量/滥用测试，也没有借此证明生产限额、队列公平性或七天删除通过。

## 下一步建议

先处理 UX-01、UX-02 和 UX-03，再复验草稿与再创作的新版本。所有修复保留独立回归步骤；不能用「页面能打开」或「check:ui 通过」替代终态与后续操作核对。

可以补充三项产品能力，但都应在流程修复后排期：

1. **草稿的明确生命周期**：有来源、最后保存时间、成功转成作品的标记；明确「新建」「沿用设定」「从原曲改写」，同时支持恢复未完成的文字。
2. **作品可恢复的通知中心/最近任务入口**：以服务端任务为准，兼顾访客、登录后认领、离开与重新打开；不要只依赖浏览器里恰好记下的歌曲 ID。
3. **导出前的真实预览与同步说明**：卡片和两种视频在下载前可预览；估算时间轴与实测对齐明确区分，为「歌词不对」报告带上可选时间点。已有报告和偏移能力应在各创作入口保持一致。

暂不建议再叠加更强的玻璃模糊或动画：先保住手机上的文字对比度、可点击区域和导出预览，避免让视觉层掩盖流程状态。
