# 歌词共创：一次三版 — 方案

> 2026-11-24。路线图里定好的一项（「歌词共创，一次三版」）；产品负责人：「继续开发吧」。

## 一句话

在创作页，写好描述后可以先让 YUHA 写三版歌词：三种写法各一版，挑一版放进歌词框，改几个字再生成。
不想挑的人照旧直接生成，歌词在生成时自动写，和现在一样。

## 为什么

歌好不好，大半在歌词。现在 AI 写的歌词要等整首歌做完才看得到；不满意只能再花一个额度重做。
先看歌词、先改歌词，把「不满意」挡在花额度之前。

## 三种写法

同一个描述、同一套歌词规则（`lyric-craft.ts`），各加一句不同的方向：

| 写法 | 给模型的方向 | 页面上叫 |
| --- | --- | --- |
| `plain` | 说得直白，像当面对那个人说话 | 直白 / まっすぐ / Plain |
| `images` | 用具体的画面说话：地方、光、物件，让感情从画面里出来 | 画面 / 情景 / Images |
| `story` | 讲成一个小故事：发生了什么，后来哪里变了 | 故事 / 物語 / Story |

三版并行请求，各自过内容检查；没写成或被拦下的那版不显示，其余照常给出。三版都失败才算这次失败。

## 用量和成本

- 沿用现有的 `POST /v1/lyrics/draft`，加 `variants: 3`。不花额度。
- 一次三版**按 3 次草稿计**（`LYRIC_DRAFTS_PER_DAY` 默认每 24 小时 10 次），因为它确实是三次模型调用。
  剩余不够 3 次时，按钮说明「今天还能写 N 次草稿」并且不让点。
- 每次三版大约 ¥0.15–0.3（gpt 系列 7 折价，见 `LYRICS_MODEL.md`）。

## 页面

- 位置：创作页「歌词：AI 写」下面。条件：有人声、描述不为空。
- 按钮「先写三版歌词看看」→ 三张卡片，每张标明写法，显示全部歌词（可滚动），底部「用这一版」。
- 选中后：歌词方式切到「我自己写」，歌词框里就是这一版，可以改。页面说明「已放进歌词框，可以改」。
- 再按一次会写新的三版（再计 3 次）。
- 访客试做（免注册）不提供：它只有一首、一分钟，草稿接口也不对 guest 开放。

## 不做的事

- 不保存草稿内容（`lyric_drafts` 只记次数，不记文字；与现在一致）。
- 不让用户自定义写法；三种够用，多了是负担。

## 验收

- 接口：`variants: 3` 返回三版、各自标明写法；计 3 次；剩余不够 3 次时拒绝且不调用模型；
  一版失败时其余照常返回；三版都失败时报错；内容检查拦下的那版不返回。
- 每种写法的那一句方向真的进了给模型的提示（按适配器测）。
- 页面：选一版后歌词框里是那一版、歌词方式是「我自己写」；`check:ui` 通过。
