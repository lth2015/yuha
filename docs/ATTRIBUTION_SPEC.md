# 来源追踪

> 产品负责人 2026-11-21：在 X 上投广告之前，先能看出每一条推广带来了什么。

## 怎么用

给广告或帖子的链接加上 `?src=名称`：

```
https://yuha.studio/?src=x-xmas-1
https://yuha.studio/pricing?lang=ja&src=x-xmas-1
```

- 名称：小写字母、数字、`-` `_` `.`，最多 48 个字符，以字母或数字开头。大写会转成小写，空格会转成 `-`；
  其它写法（含 `<`、`@`、汉字等）不算标记，直接忽略。
- 也认 `utm_campaign`，其次 `utm_source`，方便用广告平台自带的参数。
- 一个推广用一个名称，换素材或换受众就换名称（`x-xmas-1`、`x-xmas-2`），这样才能比较。

后台「统计」→「访问来源」→「推广链接（?src=）」，每个名称一行：

| 列 | 含义 |
| --- | --- |
| 访客 | 这段时间里带着这个标记浏览过的人（不含员工、爬虫） |
| 注册 | 这段时间里注册、并且是通过这个标记来的账号 |
| 做出一首歌 | 上面这些账号里，已经有一首生成成功的歌的 |
| 付费 | 上面这些账号里，付过款的（不管什么时候付的） |
| 收入 | 这些账号付的钱，退款不扣（与总收入的口径一致） |

一条推广花了多少钱，除以「注册」就是获取一个注册用户的成本，除以「付费」就是获取一个付费用户的成本。

### 2026-11-25 补充（`docs/ITERATION_EN_JA_MV.md`）

- **命名规则**：`<渠道>-<场景>-<语言>-<编号>`，如 `x-birthday-en-1`、`x-travel-ja-2`。后台按这个规则另出「按语言」「按场景」两张合计表；不按规则命名的归为一行。
- **新增两列**：「试做」= 这段时间里带着这个标记开始的免注册试做；「做出 MV」= 上面那些账号里做过视频的。「注册」不再把试做的访客算进去。
- **试做带上标记**：访客开始试做时，浏览器把标记一起发给 `POST /v1/trial/start`；试做的歌被新账号认领时，标记随之记到这个账号（只在账号没有标记、注册不满一天时）。
- **自然搜索**：没有标记、从搜索引擎的搜索结果页（Google、Bing、Yahoo 搜索等）进来的访问，按落地页记为 `seo-<页面>-<语言>`，如 `seo-birthday-en`。只记页面名和语言。同一公司的其他网站（Google 文档、Gmail、Yahoo 邮箱、Naver 博客）是别人分享的链接，不算搜索。只看落地的那一页；之后在站内打开的页面不改变来源。

## 怎么算的

- **浏览器先记下**：第一次带着标记打开网站时，浏览器把标记存 30 天（`localStorage`，`yuha.source`），
  之后每次浏览都带上。算「首次触达」：30 天内再点别的推广链接，不会把功劳从第一个推广那里拿走。
- **注册后报一次**：登录后，浏览器把标记发给 `POST /v1/me/source`，写进 `users.acquisition_source`。
  只对注册不满一天的账号生效，而且只写一次：老用户后来点了广告，不算这条广告带来的注册。
- 只记标记本身，不记任何关于这个人的信息。标记不合格就丢掉，不会因此丢掉这次浏览。

## 局限

- 同一个人换了设备或浏览器、清了浏览器数据，就看不出是哪条推广带来的。
- X 的应用内浏览器和普通浏览器是两个浏览器：在 X 里点开、后来在 Safari 里注册，这次注册不会归到这条推广。
- 访客数统计的是这段时间的浏览，注册、做歌、付费统计的是这段时间注册的账号。时间范围选得太短，
  后面几列会因为还没来得及发生而偏低。
