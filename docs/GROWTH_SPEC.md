# 拉新三件事：场景落地页、分享链路、免注册试做 — 方案

> 2026-11-22。产品负责人已确认：「按你的建议来，先做场景落地页」（每天上限 50、用 Turnstile、试做算在 2 首里、1 分钟、场景按表、授权数只给主人看）。
> 产品负责人：「1. 免注册试做：在成本受控、具备防滥用机制的前提下，让新用户尽快获得第一次成功体验。
> 2. 作品分享链路：用户生成作品后，可以得到一个漂亮、易分享、适合手机打开的页面，接收者有明确的『我也创作一首』入口。
> 3. 面向场景的落地页：比如 /birthday、/love、/memory。」
>
> 建议顺序 **3 → 2 → 1**：前两项不花生成成本，可以先上线引流；第 3 项（免注册）要先定几个数字。

## 现状（读代码和线上得到的事实）

- **新账户送 2 首**（`FREE_TRIAL_UNITS = 2`）。配置里写死了「不能超过 2」（`config.ts`，引用 PROJECT_TASK §7）。
  - 必须先注册才能用：生产环境只有 Google 登录。
- **音乐引擎只有一台 DGX，一次只生成一首**（`MUSIC_MAX_CONCURRENCY = 1`），其余的按提交顺序排队。
  - 所以免注册的真正成本不是钱，而是**排队时间**：匿名请求多了，付费用户就要等。
  - 歌词模型每首约 ¥0.05–0.1，可以忽略。
- **分享已经有一大半**（`GIFT_AND_SHARE_SPEC.md`）：
  - 送人的歌，收歌人页面有赠言和逐行亮起的歌词；
  - 每首公开的歌有自己的链接预览卡片；
  - 可以导出竖版分享视频；
  - 节日期间还有拆礼物的开场。
- **收歌人看到的「我也给一个人写一首」现在的问题**：
  - 只是一行文字链接，不够显眼；
  - 一律跳到 `/create?gift=1`，没有带上原歌的场合：别人收到一首生日歌，点进来还要自己再选「生日」；
  - 不是送人的普通歌，点进来也被打开了「送给一个人」。
- **预渲染刚上线**（`SEO_SPEC.md` 第二阶段）。新的公开页面加进 `PUBLIC_PAGES` 就会自动有中日英三份静态页，搜索引擎和大模型都读得到。
- **来源追踪已经有了**（`ATTRIBUTION_SPEC.md`）：`?src=` 记首次来源，后台「推广链接」表能看到访客 → 注册 → 做歌 → 付费。

## 一、场景落地页（先做）

### 有哪些页面

第一批 6 个，每个对应创作页已有的一个场合，或一个写什么的方向：

| 地址 | 场景 | 进创作页时 |
| --- | --- | --- |
| `/birthday` | 生日 | 送给一个人 · 场合「生日」 |
| `/love` | 告白、纪念日 | 送给一个人 · 场合「喜欢你」 |
| `/thanks` | 谢谢你：老师、父母、同事 | 送给一个人 · 场合「谢谢你」 |
| `/miss` | 想念：异地、远方的家人 | 送给一个人 · 场合「想你」 |
| `/memory` | 回忆：写给自己的一段时光，比如毕业、旅行、搬家 | 不送人，描述框放一句开头 |
| `/cheer` | 加油：考试、比赛、新工作 | 送给一个人 · 场合「加油」 |

节日期间，`/christmas` 和 `/new-year` 也照这个样子做（接节日方案）。

### 每页有什么

1. **一句标题，一段话**：说清楚这个场景下一首歌能做什么。三种语言各写一版，不直译。
2. **2–3 首示例歌**：可以直接点播放，显示歌名和一句「写给谁 / 写了什么」。
   - **只能用产品负责人自己生成并公开的歌**，不用任何真实用户的歌。
   - 示例名单写在一个配置文件里，后台不提供编辑，改名单就是改代码。
   - 不显示播放数、点赞或任何计数（CLAUDE.md：没有可见的计数）。
3. **写什么的提示**：3 个按钮，点了把一句开头放进描述框。和节日方案的提示词一样，目的是让人写出具体的人和事。
4. **一个主按钮**「为 TA 写一首」：进 `/create`，场合已经选好，带上这个页面的来源。
   - 没登录的人：一、二期去注册；三期上线后直接去试做。
5. 页脚链到其他场景页。

### SEO 和投放

- 每页加进 `PUBLIC_PAGES`：有自己的标题、描述，sitemap 自动列出，中日英各预渲染一份（`/ja/birthday.html`……）。
- 预渲染时示例歌的标题和那一句文字会写进静态页。所以**示例歌的歌名和文字必须是可以公开的内容**，这也是只用产品负责人自己的歌的原因。
- 短视频投放直接用 `yuha.studio/birthday?src=x-bday-1`，后台能按场景看转化。
- 页面不依赖登录，手机优先；`pnpm check:ui` 加上这 6 页 × 4 种宽度 × 3 种语言。

### 需要你提供

- 每个场景 2–3 首示例歌：你自己生成、设为公开，把链接给我。每页 1 首也能上线。
- 场景名单是否按上表来；要加、减或改名，告诉我。

**工作量**：约 1–1.5 天，不含示例歌。

## 二、分享链路补齐

| # | 改什么 | 为什么 |
| --- | --- | --- |
| 1 | 收歌人看到的「我也创作一首」改成**一个显眼的按钮**，放在歌词下方和页面底部两处 | 现在是一行文字链接，很容易被当成说明文字 |
| 2 | 按钮**带上原歌的场合**：生日歌 → `/create?gift=1&occasion=birthday`；普通歌 → `/create`（不打开送人） | 收到生日歌的人，最可能想写的也是生日歌 |
| 3 | 按钮带上来源：`src=share-<场合>` | 后台能看到分享带来多少新用户，这是拉新最重要的一个数 |
| 4 | **普通歌也有像样的分享页**：封面「乐谱」、歌名、歌词、大播放键，和送人的歌同一套排版，只是没有赠言 | 现在普通歌的页面是给主人用的，带着很多主人的按钮；访客看到的应该是一张干净的作品页 |
| 5 | 手机上逐项量：首屏能看到播放键，按钮不被切，360 px 宽下歌名不折成三行 | 收歌的人几乎都在手机上，从 LINE 或 X 打开 |
| 6 | 主人生成完成后，完成页直接出现「分享」：复制链接、分享视频、发 LINE | 现在要先进歌曲页再找分享菜单 |

**不做**：已读回执、播放数、收到的歌列表（与赠歌规格一致：礼物不是考核）。

**顺带发现的一处要你确认**：歌曲页对所有人显示「已售出 N 份授权」（`song.licensesSold`）。
这是一个公开可见的计数，和「不显示任何计数」的规则冲突。我建议只给主人看。要改的话这次一起改。

**工作量**：约 1 天。

## 三、免注册试做（定了数字再做）

### 做成什么样

- 首页和场景页上，没登录的人也能直接点「做一首」，**不用注册**。
- 生成完成后能听、能看歌词，能把链接发给别人。
- **下载、授权记录、再做一首都要注册。**注册后这首歌自动归到新账户里。
- 不注册的话，试做的歌 **7 天后删除**。页面上一开始就说清楚。

### 成本怎么控制

| 控制 | 建议值 | 说明 |
| --- | --- | --- |
| 每台设备 | 1 首 | 浏览器里记一个设备标记，服务器也记 |
| 每个 IP | 每天 3 首 | 一家人、一个办公室共用一个 IP，所以不设成 1 |
| **全站每天** | **N 首（建议先 50）** | 用完当天关闭，显示「今天的试做名额已满，注册即可获得 2 首」。按日本时间 0 点重置 |
| 歌的长度 | 1 分钟 | 比 2 分钟快一半，排队压力减半；仍然是一首完整的、有人声的歌 |
| **排队优先级** | **永远排在注册用户后面** | 匿名任务只在没有注册用户等待时才送给引擎，不让付费用户多等一秒 |
| 排队上限 | 匿名任务同时最多排 3 首 | 再多的话按钮显示「现在人多，稍后再试」，不让人干等 |
| 总开关 | 后台一键关闭 | 被刷、DGX 出问题、成本不对时立即停 |

### 防滥用

- **内容检查**和注册用户一样（`checkPrompt`），被拦的话说明原因。
- **人机验证**：建议用 Cloudflare Turnstile。免费，对正常用户基本无感，挡住脚本批量刷。
  - 需要在 Cloudflare 开一个账号，拿到站点密钥。
  - 不用它的话，只能靠设备和 IP 限次。设备标记清浏览器就没了，IP 换个网络也就换了，挡不住有心人；全站每天的上限是最后一道闸。
- 匿名试做的歌**默认不公开**；要分享，点「分享」时再设为公开，和注册用户一样。
- 后台统计页加一行：今天试做了几首、被拦了几次、几个人试做后注册了。

### 和「注册送 2 首」的关系

配置里规定免费额度**不能超过 2**（PROJECT_TASK §7）。所以建议：

> **试做的这 1 首算在 2 首里。** 试做后注册，账户里再得 1 首；没试做直接注册，照旧得 2 首。

这样每个人最多免费拿 2 首，规则不变，也不会出现「先匿名做一首、再注册拿两首」的绕法。

### 授权记录

授权记录（`track_licenses`）是作者和使用权的证明，以后要上链，不能挂在一个匿名的人身上。所以：

- 匿名试做的歌**没有授权记录**，也就不能下载。
- 注册、认领这首歌的那一刻，按正常流程给新账户写一条授权记录，作者就是这个账户。

### 需要你决定

1. **全站每天上限 N**：建议从 50 开始，上线后按 DGX 的排队情况调整。
2. **人机验证用不用 Cloudflare Turnstile**：要用的话，需要有人在 Cloudflare 开账号，把站点密钥配进生产环境。
3. **试做算不算在 2 首里**：建议算。
4. **试做长度**：建议 1 分钟，也可以选 30 秒或 2 分钟。

**工作量**：约 2–3 天。数据库要加迁移（匿名任务、认领、每日计数），测试多一些。

## 怎么验收

- **场景页**：6 页 × 三种语言都有预渲染的静态页，sitemap 里有；点主按钮进创作页时场合正确；`check:ui` 全过。
- **分享**：没登录的人打开一首生日歌 → 看到按钮 → 进创作页时场合是「生日」；来源记成 `share-birthday`，后台能看到。
- **试做**（按 CLAUDE.md「界面上的承诺就是测试」）：
  - 「不用注册」：无痕窗口从首页走到听到歌，全程不出现登录。
  - 「今天名额已满」：把上限设成 1，第二个设备看到满额提示，并且确实没有创建任务。
  - 「注册后归到你的账户」：注册后在「我的歌」里看到它，并且授权记录写在这个账户下。
  - 「7 天后删除」：把时间拨过 7 天跑清理，歌和音频文件都没了。
  - **「排在注册用户后面」**：同时有一首注册用户的任务和一首匿名任务，引擎先拿到注册用户的。
  - 「试做算在 2 首里」：试做后注册，账本上是 1 首，不是 2 首。

## 不做的事

- 不做公开作品广场、点赞、播放数（CLAUDE.md 范围决定）。示例歌只是你挑的几首，不是一个可以翻的列表。
- 不给匿名用户下载、不给授权。
- 不为拉新降价或加送额度。
