## 我们共享的只有两样东西

### 1. 输入帧约定（文档级契约，两边各自实现）

不论输入来自触控、鼠标还是摄像头，都先归一化成同一种帧，再交给各自的引擎。
这样第二阶段接入摄像头时，只改输入层。

```ts
type GestureFrame = {
  t: number;              // 毫秒，单调递增，从本次交互开始计
  active: boolean;        // 是否有手指/手在「按下」
  x: number;              // 0..1，左→右
  y: number;              // 0..1，下→上（向上为大）
  speed: number;          // 0..1，已平滑、已归一化的移动速度
  openness: number;       // 0..1，「张开」程度
  spread: number | null;  // 0..1，两点（两指/两手）距离；单点时为 null
  confidence: number;     // 0..1，触控恒为 1；摄像头为识别可信度
  source: 'touch' | 'pointer' | 'camera';
};
```

- 注意 `y` 向上为大，与屏幕坐标相反，这是有意为之：「抬高」应当是变大。
- 触控下的 `openness` 在 YUHA 定义为「手指停留越久越张开」（约 2 秒升到 1，
  移动时回落，抬起清零），`spread` 为两指距离。这是 YUHA 的暂定映射，
  Wonderful World 可以有自己的触控定义，只要产出的帧满足上面的形状与取值范围。
- **改约定的规则：** 任何一方想增删字段或改变取值含义，先提出、双方确认，
  再同时修改各自的文档。不悄悄扩展。

### 2. 隐私与体验原则

- 默认触控，**摄像头默认关闭**，只在用户主动开启后才加载识别模型。
- 画面只在本地识别，**永不上传**，不保存画面。
- 首次体验不需要登录，不因权限弹窗阻断第一次创造。

## 附录：锦鲤的运动原则（Wonderful World 回复，2026-10-26）

YUHA 请求后，Wonderful World 在产品负责人确认后用文字回复。按约定只共享原则，不共享代码。下面是原文要点。

**两处更正**：这些行为来自他们的产品设计（02 §4、§5），不是「送鱼」实验的结论，送鱼实验还没开始；
在他们那边，长按水面就是「召唤鱼过来」。

**验证程度**：数值都已实现，在无头浏览器里跑过，产品负责人在真机上看过整体效果，但没有针对这些数值做过
用户测试，应当作经验值。S 指屏幕短边，L 指鱼的身长。

1. **游速、转弯**：L = 0.10–0.26 S；巡游速度每秒 0.3–1.05 L；当前速度每秒向目标速度靠拢约 1.8 倍差值；
   漫游转弯约每秒 0.7 弧度，硬上限每秒 2.6 弧度；没有专门的停顿；与同伴同行时向同伴的平均速度靠拢。
2. **路径**：漫游方向由周期约 17 秒和 48 秒的两个慢正弦叠加，走大弧线；离边界约 0.9 L 时开始被推回，
   推力随深入程度线性增加，不做硬反弹；结伴意愿以约 140 秒的周期起伏，所以会聚聚散散。
3. **身体**：后一节沿前一节走过的路径跟随。横向位移 = 幅度 × sin(相位 − 5.5 s) × (0.12 + s^1.3)，
   幅度 0.03–0.08 L；相位每秒增加 3 + 5 ×（速度 ÷ L）；胸鳍张合频率是身体摆动的一半。
4. **聚拢**：被吸引约 2.5 秒，离那一点不到 0.4 L 时结束；两条鱼距离小于 0.7 ×（两者身长之和）时互相推开。
5. **确定不好的做法**：一群鱼追同一个圆会挤到一侧，必须给每条鱼分配等间距的位置；圆要按水面形状做成椭圆。

**YUHA 的取舍**（`apps/air/src/play/koi.ts`）：
- 采用他们的身体行波公式、摆动频率和胸鳍频率。
- 游得更慢，约每秒 0.15–0.3 L。湖在这里是音乐的背景，不是玩法本身。
- 聚拢时每条鱼绕自己半径的圈游，而不是追同一个圆。半径在归一化坐标里取，横屏上自然呈扁椭圆。
