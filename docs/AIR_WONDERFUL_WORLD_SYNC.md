## 一句话

YUHA 在做一个受「手势开花」启发、但不抄它的实验：**一个动作创造一段声音，
声音最终成为一首歌。** Wonderful World 是「一笔创造一个生命，生命进入一个世界」。
两者共享设计哲学：表达门槛极低、感官反馈连续、结果有审美价值。**不共享**
产品界面、品牌、后端，也不共享代码包。

## 我们共享的只有两样东西

### 1. 输入帧约定（文档级契约，两边各自实现）

不论输入来自触控、鼠标还是摄像头，都先归一化成同一种帧，再交给各自的引擎。
这样第二阶段接入摄像头时，只改输入层。

```ts
type GestureFrame = {
  t: number;              // 毫秒，单调递增，从本次交互开始计
  active: boolean;        // 是否有手指/手在「按下」
  x: number;              // 0..1，左→右
  y: number;              // 0..1，下→上（向上为大）
  speed: number;          // 0..1，已平滑、已归一化的移动速度
  openness: number;       // 0..1，「张开」程度
  spread: number | null;  // 0..1，两点（两指/两手）距离；单点时为 null
  confidence: number;     // 0..1，触控恒为 1；摄像头为识别可信度
  source: 'touch' | 'pointer' | 'camera';
};
```

- 注意 `y` 向上为大，与屏幕坐标相反，这是有意为之：「抬高」应当是变大。
- 触控下的 `openness` 在 YUHA 定义为「手指停留越久越张开」（约 2 秒升到 1，
  移动时回落，抬起清零），`spread` 为两指距离。这是 YUHA 的暂定映射，
  Wonderful World 可以有自己的触控定义，只要产出的帧满足上面的形状与取值范围。
- **改约定的规则：** 任何一方想增删字段或改变取值含义，先提出、双方确认，
  再同时修改各自的文档。不悄悄扩展。

### 2. 隐私与体验原则

- 默认触控，**摄像头默认关闭**，只在用户主动开启后才加载识别模型。
- 画面只在本地识别，**永不上传**，不保存画面。
- 首次体验不需要登录，不因权限弹窗阻断第一次创造。

### 请 Wonderful World 提供的摄像头参考说明

基于你们做 WonderLab 时「摄像头可选」的经验，用文字说明即可，不需要代码：

1. MediaPipe（或你们实际使用的方案）如何**按需**加载：首屏不加载，用户开启后
   再加载；模型文件大小与加载耗时的实测数据。
2. 权限交互：开启前如何说明、被拒绝后如何退回触控、如何再次开启。
3. iOS Safari / iPad 上的坑：权限、`playsinline`、前后台切换、发热与帧率、
   需要 HTTPS 等。
4. 你们如何从手部关键点算出「张开程度」和「两手距离」，以及如何平滑抖动。

不急，第一阶段的可用性测试（YUHA #35）通过之后才会用到。
