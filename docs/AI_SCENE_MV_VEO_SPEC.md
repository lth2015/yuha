## 1. 产品定位与首版范围

**选自己歌曲中最想分享的一段，让 AI 为它生成有统一风格的动态场景，导出竖屏音乐短片。** 先让一次生成可靠、价格可控、值得保存，再扩展时长。

| 项目 | 首版设计决定 | 产品理由 |
| --- | --- | --- |
| 默认长度 | 15 秒；两个各 8 秒镜头，合成时共裁掉约 1 秒 | 适合分享，不让费用随整首歌曲长度增加；首版不靠循环凑长度 |
| 省成本选项 | 8 秒；一个 8 秒镜头 | 以减少实际生成秒数省钱，用户能在确认前看懂差别 |
| 短歌曲 | 8–15 秒可用双镜头版，成片不长于歌曲；不足 8 秒暂仅提供快速视频 | 不伸长原音频；8–15 秒歌曲可主动选单镜头 8 秒，双镜头仍按 16 秒工作量计算并说明 |
| 不开放的长度 | 30 秒、60 秒、整首；不提供任意时长滑杆 | 避免任意秒数向上取整导致隐性成本，先验证短片采用率 |
| 模型 | 精确锁定 `veo-3.1-fast-generate-001`；拟经已有 TokenStars 网关接入，先确认视频权限与数据路径 | 不用浮动别名；禁止静默升级标准版、preview、其他模型或提供商；直连 Vertex AI 作为另需复核的方案，不自动兜底 |
| 画面 | 原生 `720p`、9:16；竖屏输出 720×1280，MP4 | 720p 指短边 720，竖屏长边 1280 符合这一上限；不生成 1080p 后压缩冒充省钱 |
| 音频 | 请求关闭模型音频（接入前验证支持），最终仅保留歌曲选段原声 | 避免重复人声、额外音频成本；后期静音不等于省去生成音频的费用 |
| 输入 | 仅文字分镜；延续三种风格及可选描述 | 不自动发送原歌、歌词、封面、照片、账号信息或历史创作资料 |
| 用户 | 已注册、拥有该首可播放歌曲；每用户最多一个活跃任务 | 访客需先注册并认领歌曲；不扩大现有年龄／购买资格 |
| 发布顺序 | 有总预算的员工内测 → 成本、质量、隐私验收 → 决定正式售价与公开开放 | 不把按秒付费 API 包进无限免费体验；员工也受预算约束 |

8 秒请求、720p、9:16、关闭音频和单样本必须在 V0 验证：如精确模型不能同时支持，停止真实生成并回报，由 Codex 修改规格；**不自动换高分辨率、有声版、其他模型或不同地区**。

首版不做照片驱动、真人／儿童照片、名人／口型、跨镜头人物一致性保证、自动生成整首、逐镜付费重抽、付费插队、自动跨区域兜底。照片 MV 的非 AI 路径继续存在，不因本次接入更改照片用途。

## 2. 用户能看到的布局与交互

### 2.1 歌曲页入口

“做视频”区域按以下顺序纵向排列，手机默认收起复杂编辑：

1. **用照片做 MV**：已有能力，仍为第一入口；保持当前真实可用状态和说明。
2. **AI 场景 MV**：卡片说明“为一段歌曲生成动态画面”，列出“8 秒 / 15 秒 · 竖屏 720p · 后台制作”；有预算与权限才可开始。内测标签仅在实际内测时显示。
3. **用封面做视频**：低优先级快速选择，也是在等待／失败时的可选路径。

不在用户流程展示 DGX、云项目、API 单价或模型部署细节；AI 服务处理说明通过确认区和详情链接提供。沿用现有间距、字体和配色，不另造一个剪辑器。功能关着就不显示可生成承诺，也不发送场景生成请求。

### 2.2 配置面板

手机为单列：**选歌曲片段 → 选画面风格 → 可选描述 → 查看分镜**。桌面可用左右两列，左边配置、右边预览；确认按钮与费用保持同一区域，手机键盘打开时不能遮住输入或错误。

- 时长为单选“8 秒（单镜头）”“15 秒（双镜头）”，默认 15 秒。短歌曲按第 1 节适配；不足 15 秒时双镜头选项改标实际成片时长，不仍写“15 秒”。确认区同时说明双镜头工作量仍为 16 秒。
- 波形／歌词片段条可拖动**起点**，终点跟随所选时长；优先 saved chorus，没有则中段。首版沿用现有播放器和时间轴，不另发音频分析请求。未提供真实波形时不画假波形。
- 同屏显示起止时间与选段歌词；提供“试听这段”，到选段末尾停。纯音乐不显示空歌词；时间轴为估计值时就地给校准入口。校准不是视频必做步骤，不在此实现第二套歌词编辑器。
- 三幅风格图：雨夜霓虹、日落海边、柔和插画。标“风格示意”，不可用静态插画冒充 Veo 实测输出。既有原创 SVG 可复用，接入前不宣传“已验证最优风格”。
- 描述可选，沿用 ≤300 字符规则（前后端统一计数）；说明“描述你想看到的场景，请勿写真实人物信息”。保留用户文字，网络失败不清空。
- “查看分镜”只生成／读取文字草稿，**不调用 Veo**。若以后引入收费文字模型，应单独纳入成本与披露，不能把“没有视频调用”说成平台零成本。

### 2.3 分镜与开始确认

15 秒版显示两张可编辑文字卡；8 秒版显示一张。每卡有预定画面、运动和实际使用时段。两镜头共享风格与色调；示例只用无人脸场景，不能承诺连续剧情或精确动作对拍。

- 用户用中／日／英查看和编辑叙述；若后台需要英文 prompt，提供可展开的“实际发送给 AI 的描述”，草稿确认版本与实际请求一致。首版可直接传经验证的用户语言；不要暗中翻译或默认认为所有用户都能读英文分镜。
- 确认卡汇总：歌曲选段、输出时长、镜头数、720p 竖屏、字幕开关、本单价格／内测配额、第三方 AI 处理说明、等待和取消规则。
- 内测显示“本次不扣歌曲额度；受内测次数限制”，不能显示无限免费。正式版若尚未定价，按钮必须保持内测限定，不出现价格占位就接受公开订单。
- 正式版显示服务器给出的**固定本单报价**，不得以 API 美元成本代替用户售价。报价失效或改了时长、镜头描述、风格、字幕等确认参数，需重新确认；不自动按新价格开始。
- 主按钮“确认并生成”，副按钮“返回修改”。双击、重复 POST、超时后重试操作都不能造成第二份外部生成。
- AI 提示文案必须在同意前能看到：**“画面描述将经 TokenStars 发送至 Google 的视频生成服务；歌曲音频、歌词和照片不会随本次画面请求发送。成片由 YUHA 配上原歌曲制作。”** 实现若与此不符，先改方案／送审，不能保留错误说明。

### 2.4 等待、离开与取消

| 状态 | 页面内容 | 可执行动作 |
| --- | --- | --- |
| 排队中 | 已接单，尚未开始画面生成；不显示虚构位置 | 返回歌曲、取消 |
| 画面生成中 | “正在生成画面”及实际已完成镜头；Veo 没有百分比时不造进度条／倒计时 | 离开、回来刷新、取消后续制作 |
| 正在合成 | “正在配上歌曲和字幕” | 离开、刷新；首版不承诺可取消合成 |
| 确认生成状态中 | 请求结果暂不确定，正在核对，不能说“已失败可免费重试” | 刷新、返回、申请停止后续制作（等服务端确认）；不发新任务 |
| 取消请求处理中 | 等待服务端确认；显示处理中，不能立即显示已取消 | 刷新；防止重复操作 |
| 已取消 | 已停止后续制作，本次不扣歌曲额度／不结算该单 | 新建前重新检查次数和预算 |
| 失败 | 固定可理解原因；技术失败不扣歌曲额度／不结算该单 | 修改描述或明确重新申请；重试不是自动免费 API 重跑 |

可以离开：任务存在服务端，关闭浏览器不终止；重新登录／回到同一歌曲能恢复。前台 10–15 秒轮询、后台暂停、回前台立即读状态；不得把恢复页面写成新建任务。完成通知先用站内状态，不新增营销邮件或浏览器通知权限。

没有实测数据时统一说明“后台制作，完成时间受服务繁忙程度影响；你可以离开后回来查看”。上线文案不能继承 LTX 的 6–12 分钟，也不能由模型名 Fast 推导“一分钟完成”。

取消文案：“停止后续制作。已提交的画面请求可能仍会完成；确认取消后本次不会结算。”外部请求可能仍计费，平台承担；后台仍须追踪未完 operation 并清理，不把 API cancel 当作退款或已停止计费的保证。

已有活跃任务时，新的入口指向现有任务，可跨歌曲跳转；不展示他人任务数量、播放量或点赞量。“完成第几个镜头”仅为本人的任务进度。

### 2.5 完成、重新合成与失败

- 完成区在同一面板预览 MP4，显示实际时长、竖屏 720p、实际 `expiresAt`；支持下载以及设备确实支持时的文件分享。打开分享面板不计为已发布。
- 声音只来自原歌；字幕默认开（纯音乐除外），与同屏歌词的快照时间轴一致；选段与字幕跨镜头不断裂。切换点可轻微调整以配合节奏，不把峰值当节拍、不改歌曲速度。
- 15 秒版两个 8 秒片段去掉约 1 秒冗余后顺序剪接，不默认循环、倒放、补黑或慢放凑时长。输出时长误差 ≤1 视频帧；音画尾差 ≤100 ms，无可听模型音频。
- 下载和分享读取真实媒体 MIME／字节；HTML 200 或错误音频 MIME 不算成功。旧本地 `/v1/files` 非 WAV 统一标音频的问题仍须修复。
- 修改字幕或重新合成不重新调用 Veo。中间片段仍在批准保留期且可访问时复用；若已清理，明确不可重合成，不能偷偷重画镜头。首版不必增加独立的字幕重合成 UI。
- 任一镜头缺失都不能用快速版冒充 AI 成片来结算；已成功镜头可用于排障，但不能跨用户复用。重新申请需要明确提示限额仍适用，故障成本由平台承担。
- 下载后用户设备上的副本不受 YUHA 远程删除控制。7 天只在后台实际按该值清理且条文审定后承诺；短期下载链接过期与成片保留期限分开。

## 3. 成本控制：减少实际生成，不只压成片

分辨率上限解决单次规格，**请求次数、生成秒数、音频、重试和并发**共同决定成本。720p 是否比其他尺寸便宜取决于提供商实际计费，不能自行假设。

设 `P` 为该精确模型、720p、无音频的已核实美元／生成秒单价。`P` 未填或报价已过复核有效期时，付费 provider 不启动；demo 和无付费文字草稿仍可用。

| 方案 | 请求数／样本数 | 正常生成秒数 | 纯生成成本公式 | 若 P 假设为 $0.10/s 的算例（非已核实价） |
| --- | --- | --- | --- | --- |
| 8 秒成片 | 1 次 × 1 样本 × 8 秒 | 8 | 8P | $0.80 |
| 15 秒成片 | 2 次 × 1 样本 × 8 秒 | 16 | 16P | $1.60 |
| 30 秒方案，本期不开放 | 4 次 × 1 样本 × 8 秒 | 32 | 32P | $3.20 |

上表不含文本处理、失败／取消的潜在供应商计费、GCP 暂存、跨云下载、AWS 编码存储流量及税费。**生成 16 秒、成片 15 秒应按实际供应商计费规则核算，不能只预算 15P。** 模型返回附带音轨后再静音不构成购买无音频 SKU 的证明。

### v2：Claude 提供的 TokenStars 文档报价

来源为 Claude 的[调研提交 `f7d8db9`](https://github.com/lth2015/yuha/blob/f7d8db9/docs/VEO_VIA_TOKENSTARS.md)，其引用 [TokenStars 英文模型文档](https://docs.tokenstars.ai/en/docs/api/ai-model/videos/veo31)。本云端访问该官方页面也被 CONNECT 403 阻挡，以下是**对 Claude 文档的交叉阅读，不是 Codex 独立取得官方正文或实际账单**：

- 文档列 Fast / 720p / 无音频 `$0.08/s`；依此算 8 秒约 `$0.64`，15 秒双镜头按 16 秒约 `$1.28`。作为当前网关报价候选，替代上表 `$0.10/s` 的纯假设用于讨论；仍须核实 `$` 结算币种、计费单位／取整、税费、模型权限及账单。不能宣称与 Google 官方价格相同或没有加价，除非另有同日期、同 SKU 官方证据。
- 文档列 4／6／8 秒、9:16、720p 和 `generate_audio=false`；首版仍使用 8 秒计划。API 映射候选：`POST /v1/video/generations`，`model`、`duration:8`、`aspect_ratio:'9:16'`、`size:'720p'`、`generate_audio:false`；单样本字段／默认行为需核实，不照抄 Vertex 的参数名。
- 提交返回 `task_id`；轮询 `GET /v1/video/generations/{task_id}` 返回 `data.status` 与完成后的 `data.url`。持久化 TokenStars 任务 ID，不能把它假装成 Google operationName；输出 URL 最小权限取回，跨主机下载不自动转发 Bearer。
- “8 秒约 75–105 秒”是网关文档测量，不是 YUHA 实测，也不直接相乘作为总等待承诺；“失败自动返还额度”不能证明网络结果未知、主动取消或用户订单退款都免费。
- “下载链接有效 24 小时”只表示链接有效期，不能推出 prompt／视频保存 24 小时，或到期自动删除。训练、留存、处理区域、取消／删除、幂等、限流与并发仍待供应商核实。

### 必须由服务端执行的约束

1. 模型、`720p`、9:16、8 秒、单样本、关闭音频锁在服务端配置／计划中，浏览器不能覆盖。具体 API 参数名在 V0 核实。无 1080p／4K 升级，也不把 Veo 尚未支持的 480p 当成请求选项；以后导出较低尺寸仅省存储流量，不宣称省掉推理费用。
2. 每单正常请求最多 1 或 2 次；默认**不自动重试新的计费生成请求**。查询 operation、重取已完成字节、重做本地合成可有限重试。确定未接收的拒绝和未知是否接收必须区分；后者不能按普通 unavailable 重新 submit。
3. 提交外部请求前，原子预留任务、用户、全站每日生成预算及并发槽；所有 worker 共用持久计数。已有 operation 只查询，不重新购买。预算耗尽时关掉“确认并生成”，直接绕接口也拒绝；不能先扣用户款再告知没预算。
4. **内测建议配置**：每员工每日最多 2 个已提交任务，全站最多 10 个任务且应用请求预算 $20/日（先触及者生效），全局最多 1 个外部镜头运行、每用户 1 个活跃任务。每日窗口采用 Asia/Tokyo，配置可下调；这些是实施默认建议，不是已设置值，也不是账户账单硬上限。日切不能释放旧任务占用的并发或漏记跨日未完成请求。
5. 单任务成本预留为实际计划秒数 × 核实单价，另纳入配置的网络／存储安全余量；没有预算配置、费率或持久计量时 fail closed。单价变化不悄悄扩大已有计划，平台承担已确认用户固定报价的差额。
6. 提交结果不确定时保留预算占用并进入核对状态；取消／失败也不能因用户不收费就从平台已发送预算中扣掉。只有确定没发出的预留可释放；外部消耗按保守估算保留并与账单对账，不随用户删除任务而丢失。
7. 禁止“失败后全单免费重跑”的隐式循环、批量抽多样本择优、后台自动换模型、换区域或重新生成。用户主动重新申请是新的预算动作；首版不出售不限次重抽。
8. 应用预算不等于 TokenStars／Google 账单实时硬熔断：计费延迟、其他调用者及网络结果不确定都会影响账单。网关受限凭据、视频模型权限、余额／配额、账单告警和日对账需配套；直连方案则另配独立项目和最小权限身份。余额不足拒绝不等于可依赖精确余额作应用并发预算；账单告警本身不会自动停机。只有本应用的已知请求受上述预留约束。

公开收费另开产品／账本小规格：平台供应商成本与用户应付额分开；Ready 且实测可下载才可结算一次，Failed／Cancelled 不结算、不消耗歌曲额度。正式售价由实测总成本、失败率、采用率和毛利决定，本次不定死日元售价，不扩展支付产品类别。新购买路径如需改变支付矩阵，先更新 `PAYMENTS_DESIGN.md` 并走统一确认页面，不能在此硬编码渠道。

## 4. 异步服务与现有实现如何衔接

```mermaid
flowchart LR
  A[选段、风格与描述] --> B[文字分镜草稿]
  B --> C[确认方案、说明与本单消耗]
  C --> D[原子检查权限、预算、唯一任务]
  D --> E[TokenStars 转发 Veo 720p 画面任务]
  E --> F[取回并检查视频]
  F --> G[AWS 合成原歌与字幕]
  G --> H[私有预览、下载、分享]
```

- 复用 `scene_mvs`、`scene_mv_shots`、所有者接口、服务端恢复、私有存储及 T6 编码。新增 Veo provider，不让分钟级生成堵住 HTTP 请求。音乐生成／歌词对齐继续走原路径，不把音乐模型迁到 Veo。
- **现有契约需要升级**：当前 `ClipRequest` 只有 prompt、1–8 秒和方向；worker 用 `ceil(span/shots)` 算时长；API 默认四分镜、最长 32 秒。这些不能直接复用成任意秒数的 Veo 请求。任务计划需持久保存每镜头合法时长、提供商、精确模型、分辨率、音频策略与能力／费率版本。
- 旧草稿不自动启动为付费 Veo；已提交 LTX 任务仍用其原 provider ID 查询，不能拿 LTX ID 发给 Veo，也不能重启后按全局新配置换模型重画。历史成片仍能在权限／保留期内下载。部署切换及旧任务排空由 Claude 单独列方案，不在本次设计工作中操作生产。
- 外部 `operationName`／任务 ID 在获得后立即持久化；跨 worker 原子领取。超时和“已接收但未记下 ID”需要明确 reconciliation 策略，无法核实时停止新增计费生成，不能承诺供应商不存在的 exactly-once。
- API 状态可沿用 `draft/queued/generating/composing/ready/failed/cancelled`，另加可识别的 `reconciling` 子阶段或独立状态；由 Claude 提交契约变更，Codex 复核后按一致版本实现。取消确认与供应商清理为不同字段／动作，不丢弃未完 operation 的追踪信息。
- 内测也必须返回真实 `plan` 和 `allowance`：8/15 秒模式、实际片长、镜头规格、画质、是否允许开始及不可开始原因。正式收费前增加不可篡改、带有效期的确认／报价版本；`start` 引用服务器保存版本，不能信任前端算出的费用。
- 全部创建／更新／查询／下载／删除仍校验歌曲所有权，普通持链接访客与他人授权购买者不因此获得生成权。用户素材、provider 响应和签名链接不进入日志或公开截图。
- 交给本地合成前 `ffprobe` 核对实际尺寸、方向、时长、帧率与媒体类型，拒绝未约定的高分辨率结果并报告，不能误宣传模型已按低成本规格请求。最终明确 map 原歌曲音轨，不能因新 provider 带音轨就混入或误判整个任务失败；无音频请求却有音轨需记录能力核验差异。
- 原有 dgxv 健康检查和“队列大于 15”报警不能当作 Veo 健康状态；监控改为认证／权限失败、429 配额、operation 延迟、未知提交、预算余量和成本。`health()` 检查不能自己触发一次收费生成。

## 5. 数据路径、保留与上线前条件

拟议数据路径：**用户文字 → YUHA（AWS 东京）→ TokenStars → Google Veo 的已批准处理区域 → 网关结果取回 → YUHA（AWS 东京）合成 → 私有成片**。TokenStars 视频上游是否 Vertex AI、具体地点、双方的数据驻留／留存／训练条款都需按视频服务合同核实；既有文字模型走 Azure 日本东部不能证明视频也在日本。

- 此次视频路径明确由 TokenStars 和 Google 接收画面文字。旧 `docs/legal/PRIVACY_CHANGES_SCENE_MV.md` 的“自有视频服务器、不经过第三方 AI”不能作为 Veo 的上线条文，原有 TokenStars 文字服务的不保存／不训练信息也不能自动套用到新视频路径及 Google。
- 只发画面 prompt 和必要生成参数；不自动发送照片、歌曲原音频、完整歌词、邮箱或用户 ID。生成描述可能本身含个人信息，提示最小化不等于保证没有个人信息。代理端日志、SDK 调试和 tracing 同样不得记录正文。
- 拟用 TokenStars：密钥仅在服务端，按现有 secret 管理方式；复用现有凭据之前确认 Veo allowlist、视频扣费余额和权限，不能因 text 能用就推定 video 已授权。上游区域不可指定或无法确认时记录为公开上线阻塞，不静默使用未知地区。直连 Vertex 若另被批准，改用最小权限工作负载身份并单独审查项目、区域和合同，不能作为网关出错的自动回退。
- 输出先取回 YUHA 私有存储，浏览器不依赖网关 24 小时链接作为 7 天交付。若实际直连需要 GCS bucket，再使用经批准区域的私有暂存并验收生命周期；不发布 bucket。网关暂存和跨云取回成本同样纳入记录。
- YUHA 成片沿用拟议 7 天，临时文件、中间片段、草稿、描述的保留与删除按审定规则实现。不能承诺调用 YUHA 删除立即抹掉供应商全部日志／备份；operation 的取消、结果清理、GCS 删除与供应商合约保留分别记录。
- 删除歌曲／账号时停止新提交，撤销访问并执行可支持的删除；只留最小化的成本对账与清理凭证，内容不因对账而无限保留。取消中的 operation 在完成后仍要尝试清理。
- 现有年龄规则、照片“不交 AI”路径继续有效。本轮不修改条款页面，不以员工内测默认放行普通用户。公开前需按真实 Google 数据流更新送审稿、产品提示与控制，不能只替换提供商名称。
