# 报告问题（私密）— 规格

> 2026-10-29。起因：朋友家孩子说「歌和歌词对不上」，我们只能猜是哪首、哪一句、哪个版本。
> 功能验收和安全测试之后，产品负责人定下的顺序是：私密问题反馈 → 任务找回 → 失败补偿记录。

## 要做到什么

作者在自己的歌旁边点「报告问题」，几秒钟说清楚哪里不对；团队在后台看到时，已经自动带上了
找原因要用的信息。**歌曲不需要公开**，团队能不能听这首歌，由作者自己决定。

## 用户这边

歌曲页（只有作者本人能看到）的「报告问题」会打开一个小表单：

| 项目 | 规则 |
| --- | --- |
| 问题类型（必选） | 漏唱或唱错 / 歌词不同步 / 杂音或音质 / 无法下载 / 其他 |
| 在第几秒（可选） | 正在播放这首歌时，自动填入当前位置，可以改 |
| 补充说明（可选） | ≤ 500 字 |
| 允许客服收听这首歌（可选，默认不勾） | 不勾的话，团队只能看到文字信息，听不到音频 |

- 提交后显示「已收到」和报告编号，下面列出这首歌之前的报告和处理状态。
- 下载失败的错误提示旁边有「报告这个问题」，点开时问题类型已经选好「无法下载」，
  并带上那次失败的「问题编号」（请求 ID）。
- 限速：每人每小时 10 条。

## 自动附带的信息（用户不用填）

歌曲 ID、生成任务 ID、音乐引擎的请求 ID、歌曲时长和状态、歌词时间轴的来源（估算 / 对齐 /
手动校正）和对齐器、提交时的浏览器 UA、客户端带来的请求 ID。**不附带**账户邮箱以外的身份信息，
后台显示邮箱时和其他地方一样按角色打码。

## 团队这边（后台「审核」页）

- 列表：未处理的报告，按时间倒序，显示类型、歌名、第几秒、说明、自动信息、是否允许收听。
- **收听**：只有作者勾了「允许收听」才有这个按钮。点击时签发一条短时效的音频链接，并写审计日志
  （谁、什么时候、听了哪份报告的音频）。没勾就没有这个按钮，接口也会拒绝。
- **处理完成**：填写处理说明（≥ 5 字），写审计日志。作者在歌曲页能看到这份报告变成「已处理」
  和处理说明。

## 不做的事

- 不做公开的问题列表、点赞、计数；报告只有作者本人和员工能看到。
- 不自动退还额度。补偿是下一项「失败补偿记录」的事，处理说明里可以写明已补偿。
- 注销账户时，这个账户的报告一起删除。删除歌曲时，报告保留，但音频已经不在，收听按钮也就没有了。

## 验收

- 作者能提交、能看到自己的报告和状态；别人（包括知道歌曲 ID 的人）既不能提交也看不到，
  会得到和「歌曲不存在」一样的 404。
- 没有允许收听时，员工拿不到音频链接；允许时能拿到，而且留下审计记录。
- 下载失败提示里的「报告这个问题」带上了请求 ID。
- 三种语言，360 / 393 / 768 / 1280 宽度（`pnpm check:ui`）。
