# 官方 BGM Marketplace

2026-11-27 · Codex 接手产品、交互、导入和后端实现。目标是把 dgxa 生成的官方 BGM 交付成可以筛选、试听和审核的曲库。

## 产品流程

1. 运营用本地文件、生成批次清单和结果记录查看候选目录。清单命令只读，核对母带实际格式、时长和重复项。导入需明确传入要纳入的候选项，重复运行返回原草稿。目标整批 30 首，可先导入完成的部分。
2. 管理员在后台试听对应片段。后台分别提供「审核通过」「上架试听」「下架」，写入理由和审计记录。只有审核通过的作品可上架。下架停止签发新试听链接。重新发布先经审核。
3. 访问者从 Marketplace 按风格筛选或按标题搜索，显示完整作品长度、风格和使用场景。选择一首时打开共用的试听面板，可播放、暂停、定位和重复播放。加载、未开启、空目录、无搜索结果和播放失败各有明确反馈。
4. 试听开放位可设为关闭、员工或全部。公开展示仅包括审核并上架的官方曲目。定价与授权未定前，此阶段提供试听。

## 实现和验证

- 材料送入现有私有存储。原始母带与重新编码的试听对象分开，试听最长 60 秒、128 kbps。默认从曲目中段取样，可在导入清单指定起点。公开接口只签出已上架曲目的试听对象，签名时长有限。
- 官方目录有独立审核记录和资产 ID。它不从用户作品或现有签名分享链接聚合歌曲，也不创建虚假的用户生成任务、购买记录或授权快照。现有单曲购买流程继续负责其原有对象。
- 先验「导入草稿 → 员工试听」，再验「审核 → 上架 → 访客试听 → 下架」。最后覆盖目录搜索与移动端。主测试在 API 真实读取与实际 MP3 交界处，验证角色、状态顺序、播放资产、幂等和无效来源。浏览器验证真实音频、状态切换和三语布局。
- 导入路径使用本地文件。现有安全和发布流程适用于工作分支。上线正式数据时由有权访问私有母带的运营人员执行导入和审核。

## 运营入口

DGX 上的原始批次可先用 [DGX 盘点脚本](../deploy/dgx/music/README.md#official-bgm-batches-serverbench_official_inventorypy) 检查。以下导入格式对应本轮生成脚本的 MP3 批次，每批最多 30 首。批次目录保留 `catalog.json`，把 dgxa 返回的 `dgxa-results.json` 与候选 MP3 放在它下面的 `output-dgxa/`。在仓库根目录运行以下命令。

```sh
# 读取本地文件并检查候选资格
pnpm marketplace:bgm --dir /absolute/YUHA-BGM-30

# 使用目标环境的私有存储和数据库，明确选择先导入的曲目
pnpm marketplace:bgm --dir /absolute/YUHA-BGM-30 --apply --only 01,02

# 或导入批次内全部已完成的候选
pnpm marketplace:bgm --dir /absolute/YUHA-BGM-30 --apply --all-candidates
```

写入前先应用数据库迁移。相同批次、编号、音频和元数据可重跑。同一母带只对应一条目录记录，试听起点在首次导入前确定。更换母带时使用新批次标识，保留旧记录的审计历史。审核时也应听原文件，确认整首曲目的音质。管理员在 `/admin/marketplace` 留档审核，之后才可单独上架试听。试听开关 `OFFICIAL_BGM_MARKETPLACE` 默认 `off`，可按顺序切到 `staff` 或 `all`。已签出的试听链接至多再有效五分钟，确认下架即停止签发新链接。
