## 1. 按需加载识别模型

- 【经验】首屏不加载任何非必要的东西；识别模型和推理库同样不应进入首屏包。
- 【建议】用动态 `import()` 加载推理库，模型文件在用户点「开启手势」之后才请求。加载期间触控照常可用。
- 【建议】下载和初始化分成两个可观察的阶段；界面上只说「正在准备」，不显示百分比。
- 【建议】实测方法：真机、关缓存、Fast 3G 与 4G 各量一次，分四段记录：推理库 JS 下载、wasm 下载与编译、模型文件下载、第一次推理出结果；分清「首次」与「已缓存」。模型大小以自己打包的实际文件为准。
- 【建议】模型和 wasm 从自己的域名提供，不从第三方 CDN 加载。

## 2. 权限交互

- 【经验】首次访问不弹任何权限请求；默认触控，单指玩法必须独立成立。
- 【建议】调 `getUserMedia` 之前，先用自己的界面说明：画面只在这台设备上识别、不上传、不保存。用户点「开启」才弹系统权限框。
- 【已知】拒绝为 `NotAllowedError`，没有摄像头为 `NotFoundError`，被占用为 `NotReadableError`。三种都安静退回触控，用一行字说明，不弹窗、不反复请求。
- 【已知】Safari 中用户一旦拒绝，网页不能再弹权限框，要到网站设置（地址栏「大小」→ 网站设置 → 相机）里改；「再次开启」的入口要告诉用户去哪里改。
- 【已知】Safari 对 `navigator.permissions.query({name:'camera'})` 支持有限，不要靠它判断状态，直接调用再处理异常。
- 【建议】摄像头开启时始终有看得见的「关闭摄像头」；关闭时对每个 track 调 `stop()`。

## 3. iOS Safari / iPad 的坑

- 【已知】`getUserMedia` 只在 HTTPS 或 localhost 下可用；局域网 IP 真机调试需要 HTTPS（自签证书或隧道）。
- 【已知】`<video>` 要设 `playsinline`、`muted`、`autoplay`，否则全屏播放或不出画面；隐藏视频用视觉隐藏，不用 `display:none`。
- 【经验】iPhone 上页面常挂在后台、不重新加载，只触发 `visibilitychange`；他们的声音在后台 `suspend()`、回来 `resume()`。
- 【建议】摄像头同理：切到后台停掉 track，回来重新请求流，不假设流还活着。
- 【建议】发热与帧率：约 640×480；推理 15–30 fps，与 60 fps 画面解耦并插值；有 `requestVideoFrameCallback` 时用它驱动推理；老款 iPhone 连续玩 5 分钟，看帧率与机身温度。
- 【已知】前置摄像头画面要水平镜像，在归一化成帧的那一层统一做。
- 【建议】添加到主屏幕的独立应用模式在旧版 iOS 上摄像头行为有过问题；要用这个模式须专门测。

## 4. 张开程度、两手距离与平滑

关键点算法全是【建议】；归一化与平滑的思路来自他们笔性测量的【经验】：用像素量会因设备而变（改为「画面短边 / 秒」）；手抖会被算成动作（先等距重采样，再 `[1,2,1]/4` 平滑两遍，再量）。迁移到关键点：**用手自身的尺寸做尺子，在平滑之后再量。**

- **张开程度：** `palm` = 手腕(0) 到中指根(9) 的距离；`openness_raw` = 五个指尖(4/8/12/16/20) 到手腕距离的平均 ÷ `palm`。握拳与张开的读数因人而异：先采几位同事「握拳、半张、全张」的读数再定区间，线性映射到 0..1 并夹紧。
- **两手距离：** 两只手 9 号点的距离 ÷ 画面短边；只有一只手时为 `null`。只用距离，不依赖左右手身份（可能在帧间跳变）。
- **平滑：** One Euro 滤波器（慢时去抖、快时跟手）。低置信度帧保持上一帧并缓慢衰减，不跳到 0。离散状态加回滞：超过 0.6 才算张开，低于 0.4 才算收拢。
- **speed：** 同样按「画面短边 / 秒」、平滑之后计算，再映射到 0..1；`confidence` 用手部置信度。
